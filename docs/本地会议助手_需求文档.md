# 本地会议助手需求文档

版本：V0.6（补充工作区、原稿复制与自动总结设计）

日期：2026年10月18日  
首期范围：macOS 桌面个人版  
配套文档：[本地会议助手技术方案](./本地会议助手_技术方案.md)

## 1 产品定位与核心目标

开发一个以本地录音和本地转写为基础的个人会议助手。用户在电脑上开启会议录制后，应用持续保存音频，使用 Whisper 将语音转换为带时间戳的文字，再由用户配置的大模型提供阶段总结、会议问答、待办提取和会后纪要。

**核心体验：打开应用即可录制，会议中随时看文字、问问题、看待办，会议后得到可核对、可修改、可导出的会议记录。**

产品首先满足本人在 Mac 上测试和日常使用的需要。首期采用单设备、单本地用户模式，每个使用者可以设置自己的助手模板和模型配置；这里的“每个人”不涉及同一场会议中的多人在线协作或账号体系。

### 1.1 能力分工

| 能力 | 处理位置 | 依赖 |
| --- | --- | --- |
| 录音与音频保存 | 本机 | 系统音频采集权限 |
| 语音转文字 | 本机 | whisper.cpp 与 ggml-large-v3-turbo 模型 |
| 阶段总结与待办提取 | 本地或远程，由用户选择 | 用户配置的文本大模型 |
| 会议问答与会后纪要 | 本地或远程，由用户选择 | 用户配置的文本大模型 |
| 会议记录与设置保存 | 本机 | 本地文件和数据库 |

“本地会议助手”表示录音和转写默认在本机完成。使用远程大模型时，相关会议文字会发送到所选服务，界面必须清楚显示这一状态。音频默认不发送给远程大模型。

### 1.2 首期成功标准

- 能稳定完成一场两小时会议的录音、转写、回听与保存。
- 会议中能查看持续更新的转写、阶段总结和待办候选。
- 能围绕当前会议提问，并通过回答中的引用返回原文和录音位置。
- 停止录音后，可以核对和导出会议纪要与待办。
- 断网或未配置大模型时，仍能录音、转写、回听和导出文字。

## 2 首期范围与后续规划

P0 是首期必须交付的范围；P1 是首期验证通过后再增加的体验。

| 范围 | 优先级 | 说明 |

## 3 典型使用流程

### 3.1 会前

1. 首次使用时选择模型文件或下载转写模型，并完成本机性能检查。
2. 选择麦克风；线上会议可额外打开“录制电脑声音”。
3. 选择会议助手模板，填写会议名称、目标、可选议程和参会人名单。
4. 选择本场分析模式：仅录音转写、本地大模型分析、远程大模型分析。
5. 点击“开始录制”。未配置大模型不阻止开始；转写模型未就绪时，也允许明确选择“先录音，稍后转写”。

### 3.2 会中

1. 音频持续保存；文字区持续展示已确认文本和最新识别中的文本。
2. 默认只录音转写；主动开启自动总结后，按实时/1 分钟/3 分钟模式更新讨论主题、脉络及待办候选。该新策略待开发，当前版本仍使用旧间隔。
3. 用户可点击“现在总结”，或输入“刚才有哪些决定”“我需要做什么”等问题。
4. 用户可添加手工笔记、标记重点，并确认或修改待办。
5. 暂停停止音频采集并冻结自动总结新派发；已保存音频可继续转写，在途分析可正常完成；恢复后继续同一场会议。

### 3.3 会后

1. 点击“结束会议”后立即停止录音，界面进入“整理中”。
2. 完成尾段转写与尚未处理的录音，用户按会议类型生成带覆盖范围说明的会后纪要；自动生成需有独立选项，不与自动总结混为一项。
3. 用户核对结论、待办、负责人和截止时间；可以点击证据回听。
4. 用户导出纪要、转写文本和待办；音频可单独导出。
5. 后续打开会议时，仍可以问答、编辑或重新生成纪要。

## 4 录音与音频管理

### 4.1 音源选择

支持三种模式：麦克风、电脑声音、麦克风加电脑声音。默认使用麦克风。

“电脑声音”包括会议软件/浏览器在本机播放的远端参会人声音；“本人声音”来自用户选择的内置、耳机或 USB 麦克风。线上会议预设明确选择双音源，建议麦克风与会议软件一致；不能假定只采其中一路便包含完整双方对话。

- 麦克风模式用于线下会议。
- 电脑声音模式用于只需要记录远端播放内容的场景。
- 双音源模式用于线上会议，两个音源分别保存，转写时对齐后混合处理。
- 首期电脑声音采用系统级采集并排除本应用回放音频；按特定应用筛选声音可放入 P1。
- 电脑声音功能不保存屏幕视频。系统可能要求授予屏幕或音频采集相关权限，授权文案应解释用途。

每个已启用音源显示独立音量指示，开始前提供短时电平预览。权限被拒绝或某个音源不可用时，明确说明缺失的音源，允许用户调整后继续，不能显示“录制正常”掩盖失败。

线上会议建议使用耳机，减少麦克风再次拾取扬声器声音。首期不承诺在所有外放环境下消除回声。

系统级采集可能包含其他应用、通知和音乐，录制界面需显示采集范围。会议软件中的静音不代表本助手停止采集麦克风；本助手提供独立麦克风关闭/恢复控制及常驻状态，关闭期间不采集该路，电脑声音可继续；暂停后继续需明确恢复麦克风，不能自动重新开启。两路音源不等于两位说话人，不据此自动标注姓名。

预览由用户主动开启，关闭即释放，不落盘或转写。录制中单路失败进入“部分录制”，保留另一条已选音源，明确记录缺失；不能以低电平把正常静音判为故障。首次启动失败仍遵循 R02 回滚规则。逐路降级已接入，真实权限和设备故障仍需按用例验收。

### 4.2 录制控制

- 提供开始、暂停、继续、结束四个动作。
- 录制时常驻显示状态、有效录音时长、音量和保存状态。
- 暂停期间不采集音频，不生成隐藏录音；记录暂停和恢复的实际时间。
- 切到其他应用或最小化窗口后继续录制。
- 录制时关闭主窗口保留菜单栏录制状态；退出应用需要用户选择结束或取消。
- 不把合盖、系统睡眠期间描述为可持续录音。发生中断时记录缺失区间，并在恢复后提示。
- 耳机断开或输入设备失效时显示告警。首期不静默切换到另一个麦克风，避免未经用户预期扩大采集范围。

### 4.3 保存与恢复

- 录音边录边写入本地分段文件，不能等会议结束才整体保存。
- 保存为面向语音回听的 WAV，建议每个音源 16kHz、16bit、单声道；这是语音存档，不是设备原采样率的高保真存档。
- 目标每 5 秒或更短时间刷新持久化数据。异常退出后恢复所有已成功写入的音频；强制断电时的实际损失窗口需实测。
- 提供磁盘剩余空间检测。空间不足时明确停止录音并保留已有记录，不能继续显示录音中。
- 历史会议支持重命名、删除和导出。删除需确认，清理关联音频、文本、缓存和分析结果；已导出的外部副本不受应用控制。

## 5 本地实时转写

### 5.1 基础要求

- 使用 whisper.cpp 加载 `ggml-large-v3-turbo.bin`，默认在本地完成识别。
- 默认按中文会议配置，用户可切换自动语言识别或英文；首期不提供实时翻译。
- 每段转写包含起止时间和稳定标识，支持点击回听、搜索和手工纠正。
- 未确认的识别结果使用较浅文字，并标记“识别中”；确认后作为正常正文展示。
- 新内容自动跟随滚动；用户向上阅读时停止自动滚动，提供“回到最新”按钮。
- 自动补充标点，但不承诺专有名词、口音、多人重叠讲话完全正确。

### 5.2 实时性的定义

这里的实时转写是“持续采集、分段识别、不断更新”。最新一句允许在确认前修订，不承诺每个字说出后立即固定显示。

性能合格设备上，已预热情况下的首段可读文字目标为 5 秒以内，正常连续发言时已确认文本相对音频的延迟目标为 10 秒以内，P95 不超过 15 秒。以上为设计目标，须通过真实 Mac 测试后固化。

### 5.3 异常与修订

- 转写跟不上时显示“转写落后约 XX 秒”，录音继续保存，积压音频等待补转。
- 默认不丢弃积压音频，不悄悄切换云端转写；可由用户选择性能模式或改为会后处理。
- 无声音时不应持续生成重复句或无依据的文字。
- 说话人身份默认未知。参会人名单只提供上下文，不能把一段声音直接认定为某个人。
- 用户纠正后的文本保留原始识别版本。相关纪要和待办显示“原文已更新”，用户可重新生成。

## 6 会议纪要与待办提取

### 6.1 触发方式

| 触发 | 默认行为 |
| --- | --- |
| 实时 | 新一轮约 60 字或 15 秒且有未总结的已确认文字时触发；上轮完成后才重新计算 |
| 定时 | 1 分钟或 3 分钟，窗口计时扣除暂停；没有新增内容不请求 |
| 手工 | 点击“立即更新纪要”，分析截至当前已确认的内容，与同范围在途更新去重 |
| 会议结束 | 停止周期；自动总结已开启且有尾段残余时最多补一轮；纪要独立按需生成 |

以上是下一扩展版本目标，当前尚未接入。自动更新为独立开关及实时/1/3 分钟三档，默认关闭，保留手工入口。60 字/15 秒为初始待验证参数，不表示十五秒内必定显示结果。等待上轮完整业务任务结束后再开启新窗口；等待期间的新文字保留给下轮输入，但不令返回后立即重复请求。会议纪要状态和待办提取共享任务，不重复排队。旧 5/10 分钟设置保留兼容状态，显式选择新档后才生效，不能静默提高频率。

### 6.2 实时更新内容

主卡输出当前主题、讨论脉络提纲、关键进展、分歧/未决问题，以及待办候选入口。提纲按实际内容归纳目标、问题、方案/观点、依据及结论，不填充未讨论环节；推断关系标为助手归纳，不冒充原文明示。用户关注重点可以影响顺序，但不能省略事实依据。

每个纪要版本显示：覆盖的录音时间范围、生成时间、使用的助手和模型、是否存在转写缺失。实时版本保留历史，不只维护一个不断覆盖的文本框；会后整理在同一套纪要上进入待确认状态。

主视图只展示当前机器版本，历史更新可展开。未完成请求保留旧内容并显示截至时间；人工纪要、旧人工 stage 版本不可覆盖。新总结采用增量文字及必要原文证据，不每十五秒重发整场全文。失败/取消不推进成功覆盖，连续失败暂停；问答优先于下一轮自动请求。完整状态机见[工作区优化方案](./会议工作区与自动总结优化方案.md)。

### 6.3 待办字段与确认规则

| 字段 | 规则 |
| --- | --- |
| 事项 | 用具体动作描述，不把泛泛讨论直接写成任务 |
| 负责人 | 原文明确时提取；没有明确时标为“待确认” |
| 截止时间 | 保留原始说法；能根据证据发言时的当地日期和会议时区确定时才转为日期 |
| 依据 | 关联原文片段和时间戳，可点击回听 |
| 确认状态 | 待确认、已确认、已忽略 |
| 执行状态 | 未开始、进行中、已完成；与确认状态分开 |
| 变更说明 | 后续讨论修改了负责人、时间或内容时展示变化 |

示例：原文“张总下周三把方案发出来”，可以提取事项和负责人文字线索；若参会人存在多个“张总”，负责人仍为待确认。原文“后面考虑做个方案”只属于建议，不应自动转成已确认待办。

同一事项不重复创建。用户修改或确认过的内容不被后续模型结果静默覆盖；助手提供变更建议，由用户接受。原文没有明确完成某项工作时，不自动标记已完成。

## 7 个性化会议助手

### 7.1 设计建议

首期使用“会议助手模板”这一产品概念。模板包含角色说明、关注重点和输出规则，底层以版本化配置和 Markdown 指令保存。产品中无需要求普通用户理解 Skill。

角色人设描述“以什么视角看会议”；Skill 描述“如何完成具体工作”。后续需要接入技能生态时，可以把总结、待办提取、评审观察等能力封装为独立 Skill。首期无需技能市场、脚本执行或复杂 Agent 编排。下一扩展版本采用会议类型和受限对话引擎，范围见 7.4；不因此开放通用开发工具。

### 7.2 模板配置

| 配置 | 示例 |
| --- | --- |
| 名称与角色 | 项目推进助手，站在项目经理视角整理会议 |
| 关注重点 | 里程碑、阻塞、跨团队依赖、待决策事项 |
| 输出风格 | 中文、简洁，按主题整理 |
| 纪要结构 | 核心结论、进展、风险、待办、待决策 |
| 待办提取规则 | 保留负责人和截止时间的原文，不补造信息 |
| 会议信息 | 本场目标、议程、参会人、术语；只对本场生效 |

模板可新建、复制、编辑和设为默认，内置“通用会议助手”和“项目推进助手”。首期每场会议使用一个助手，配置快照随会议保存。

会中切换助手只影响后续分析。原有输出保留原模板信息，重新生成时创建新版本。助手始终遵守应用的证据和数据处理规则，模板不能自行开启录音上传、执行程序或修改外部系统。

### 7.3 会议问答

支持问题示例：

- 刚才明确了哪些决定，还有哪些没有定？
- 哪些事情需要我跟进？依据是什么？
- 关于某个方案，支持和反对的理由分别是什么？
- 截至现在，项目最大的阻塞是什么？
- 按项目推进助手的视角，整理下一步行动。

默认只回答当前会议范围内的问题。每次回答显示“依据截至 XX:XX 的已确认内容”，关键结论包含可点击原文引用。当前会议没有依据时，明确回答“会议中未明确”；分析建议与会议事实分开标注。

用户可选择“整场已记录内容”“最近 10 分钟”或“选中文本”提问。历史较长或检索未覆盖全部内容时，需要说明回答范围，不能把部分检索结果描述为完整穷尽。

### 7.4 会议类型与持续对话（下一扩展版本，待开发）

现有运行版只提供通用/项目模板和单次问答；以下是新增目标，不能据此视为已实现。

内置周会、方案评审、决策、复盘、头脑风暴和通用六种类型。类型规定检查维度，模板规定具体清单、纪要章节、分阶段指令与快捷问题，模型配置保持独立。同类型可以有多个模板，每场绑定一个类型与不可变模板版本。用户编辑创建新版本，显式采用才影响旧会议的后续分析；历史输出保留来源，不自动猜测旧会议类型。

周会关注目标/进展/偏差/阻塞/依赖；方案评审关注约束、备选方案、假设、风险、验证及通过条件；决策会关注选项、标准、决策人、决策状态和未决条件。复盘区分事实与原因假设，头脑风暴区分想法与已采纳行动。公共证据与人工确认规则不随类型变化。

每场默认一个可持久化对话，会前协助准备，会中发现缺口，会后核对结论，支持连续追问及重启恢复。提示词由固定规则、类型清单、阶段、本场背景、问题意图、历史与证据组合。聊天历史帮助理解指代，不能替代原始证据。用户可选择历史会议沟通；录制 A、查看/对话 B 时，采集目标仍为 A，界面同时标明两者。

“目前有什么目标没有澄清、有什么卡点”应返回已知事实、待澄清项、明确阻塞、推测风险/建议和范围。没有提及不等于现实中没有；覆盖性问题必须检查请求范围的全部已确认文字，否则明确部分覆盖。流式预览和 partial 转写不能当作已校验证据。

新增聊天授权范围覆盖问题、相关历史回答和补充背景，旧分析授权不自动扩大。Agent 仅使用本场只读工具，写操作提供候选由用户接受；首版不含跨会议记忆、自动对外发言和外部动作。Pi SDK 为候选实现，代码放 agent/，接入及安全/打包实验通过后启用。详见[会议类型与对话助手方案](./会议类型与对话助手方案.md)。

## 8 会后纪要与导出

### 8.1 默认纪要结构

1. 会议名称、日期、实际录音范围和参会人。
2. 会议目标与议题。
3. 核心结论和已达成决定。
4. 按议题整理的讨论摘要。
5. 待办事项，包含负责人、截止时间、确认状态和依据。
6. 未解决问题、风险和待决策事项。

参会人名单来自用户填写或人工确认，不根据声音自动识别。纪要先作为草稿，允许修改后确认。重新生成保留旧版本，人工编辑不被覆盖。

如果部分录音尚未转写、转写失败或模型没有覆盖全部内容，纪要标记“内容不完整”并列出区间。不能只依据阶段总结便宣称已核对整场会议。

### 8.2 导出范围

| 内容 | P0 格式 | 说明 |
| --- | --- | --- |
| 会议纪要 | Markdown | 包含总结、决定、待办和证据时间戳 |
| 完整转写 | TXT、Markdown | 保留时间戳；默认导出人工修订后的版本 |
| 待办清单 | Markdown、CSV | 对表格特殊字符和公式前缀安全转义 |
| 会议录音 | WAV | 单音源可直接导出；双音源可导出混音或各音轨 |

导出的时间戳与音频一一对应。应用内链接可以定位原文；外部 Markdown 至少保留可读时间戳，不依赖只有应用才能解释的引用。

## 9 大模型配置与数据边界

### 9.1 设置项

统一提供“文本分析模型”设置：连接名称、服务地址 Base URL、API 协议、API Key、模型名称、上下文容量、输出长度上限、请求超时和连接测试。

- 首期支持一类 OpenAI-compatible 文本对话接口；并不代表所有厂商的全部功能都兼容。
- 支持用户填写本地模型服务，例如已自行安装的 Ollama；应用首期不负责安装或管理文本大模型。
- 支持保存多个文本分析配置，新增、编辑、复制、测试、设为默认、停用和删除；同一服务可保存不同模型或账号。
- 每场会议选择一个配置版本，用于本场总结、问答和待办。全局默认只初始化新会议；支持会中切换，不影响录音和本地 Whisper 转写。
- 编辑配置产生新版本，已有会议保留原绑定，显式采用后才生效；旧结果保留原模型信息，重新生成不覆盖人工编辑。失败不自动换服务。
- API Key 存入系统凭据管理服务，界面只展示掩码；日志和导出文件中不包含密钥。
- 同地址多配置凭据独立；复制默认不复制 Key，变更地址需重新指定凭据。停用/删除保留脱敏历史，受影响会议提示重选，不自动采用默认模型。
- 连接测试使用无会议内容的测试文本，验证模型可用、流式输出及结构化输出能力。

### 9.2 三种工作模式

| 模式 | 录音与转写 | 总结和问答 | 对外发送 |
| --- | --- | --- | --- |
| 仅录音转写 | 本地 | 关闭，可稍后分析 | 不发送会议内容 |
| 本地模型分析 | 本地 | 调用本地服务 | 应用只连接本地分析地址；用户自建服务自身行为由其配置决定 |
| 远程模型分析 | 本地 | 调用选定远程服务 | 发送所需文字、会议信息和相关历史上下文；默认不发音频 |

首次启用远程分析时，让用户清楚选择是否用于当前会议，以及是否允许后续阶段自动分析。用户主动配置并启用后，无需每轮重复确认。新总结上下文包含未总结转写、相关旧总结及其原文证据和本场背景，旧授权不足时需明确确认该范围；不因此包含整段聊天历史。切换服务商或扩大范围时重新展示说明。

会中切换绑定到新配置版本；旧队列取消，在途请求尽力取消且迟到结果不能写回。切到远程配置或采用新版本时重新确认本场目标及文字范围；选择配置本身不触发历史全文补发。无关配置编辑、全局默认变化不撤销其他会议授权。凭据清除/轮换只影响其引用者。

会议信息、转写和纪要默认保存在本地；首期不做云同步。录音开始前保留简短的知情录制提醒。应用不自动发送纪要或通知其他参会人。

## 10 界面设计要求

### 10.1 信息结构

只设置三个主要入口：会议、助手、设置。会议为默认入口，历史列表可以收起。

会议工作区采用以下结构：

- 顶部：会议名称、录制状态、有效时长、音源、暂停与结束。
- 中间主区：会议记录，含“实时记录 / 对话原稿”，保留手工笔记、修订和回听；原稿明确当前修订版/原始识别版，可一键复制已确认全文。
- 右侧分析区：会议纪要、行动事项两个标签；会议纪要通过实时更新、待确认、已确认、需要重新确认和覆盖不完整等状态表达生命周期。会议助手由统一悬浮入口打开，未生成可确认版本时也可查看实时纪要。
- 底部：轻量播放器和提问输入区，随当前标签呈现，避免堆叠多个工具栏。

会后沿用同一工作区，把录制控制换成回听、编辑和导出，减少学习成本。窗口较窄时上下排列、记录区可收起，右侧三个分析标签仍一致，录制控制固定可见。

本节是下一扩展版本设计，当前概览/待办/问答页面尚未替换。自动总结设置在总结标签，模型/授权放独立本场分析设置；三个模块不共用一份版本选择器。原稿复制不包含识别中预览、总结、笔记或界面控件；搜索不改变“复制全文”范围，复制按点击时的会议/来源/修订快照完成。没有文字或剪贴板写入失败不能显示成功。详见[页面方案](./会议工作区与自动总结优化方案.md)。

### 10.2 视觉与交互

- 浅色默认，支持跟随系统深浅色；使用清晰字阶、留白和少量强调色。
- 红色只用于录制和停止等重要状态，不用多色大屏表现普通会议。
- 首屏突出“开始会议”，高级模型参数放在设置中。
- 生成中展示文字进度与可取消状态，不让整个工作区被加载遮罩锁住。
- 错误提示给出具体恢复动作，例如“重试转写”“检查麦克风”“改为仅录音”。
- 重要状态不能只靠颜色区分；支持键盘操作、可读字号和系统缩放。

## 11 非功能要求与验收

下表为首期建议验收口径。性能与准确率数字是目标，不是对 Whisper 在所有机器和所有声学条件下的承诺。

| 编号 | 验收项 | 验收方法与通过条件 |
| --- | --- | --- |
| A01 | 本地录制 | 连续录制 2 小时，音频可回放，持续讲话无未提示的缺段 |
| A02 | 双音源 | 戴耳机进行一场线上会议，本人和远端声音均可回听；各自电平可见 |
| A03 | 暂停与继续 | 暂停期间无音频采集，恢复后时间戳与回听位置一致 |
| A04 | 转写时延 | 在登记的 Mac 上预热后测试；首段目标不超过 5 秒，确认延迟 P95 目标不超过 15 秒 |
| A05 | 转写质量 | 使用至少 30 分钟人工标注的清晰中文会议，规范化 CER 目标不超过 15%；噪声与重叠讲话单列结果 |
| A06 | 边界与静音 | 句子跨切片边界时无明显重复或漏句；连续 5 分钟静音不产生持续幻觉文本 |
| A07 | 离线使用 | 断网后仍可录音、转写、搜索、回听和导出；分析功能按本地服务可用情况运行 |
| A08 | 总结有依据 | 人工抽查的关键结论均能返回原文；无依据的负责人、日期和决定不作为已确认事实 |
| A09 | 待办可控 | 至少 30 条人工标注待办测试；明确待办提取准确率目标不低于 90%、召回率目标不低于 80%，数字随模型评估固化 |
| A10 | 人工结果保留 | 人工修改待办或纪要后重新分析，旧版本与人工修改均不被静默覆盖 |
| A11 | 故障恢复 | 强制终止应用后可恢复已写音频、会议记录和未完成任务；可从缺失区间继续转写 |
| A12 | 模型与网络异常 | 断网、429、超时、无效密钥不影响录音；显示失败和重试入口，不重复创建待办 |
| A13 | 设备与磁盘异常 | 拔掉耳机、撤回权限、磁盘不足时产生明确状态与缺失记录 |
| A14 | 数据边界 | 网络检查确认 ASR 无会议音频外传；远程分析只发送用户授权的文字范围，密钥不进前端日志 |
| A15 | 导出一致性 | 导出的纪要、待办和转写对应选定版本，时间戳可在音频中核对 |

CER 为字符错误率，计算方式与标点、大小写、简繁体等规范化方法见技术方案。中文、英文和混合会议应分别报告，避免用一个数字掩盖差异。

## 13 后续跨平台原则

- Windows 第二步适配，先复用会议数据、助手模板、分析逻辑和界面，再替换音频采集与系统凭据实现。
- iPhone 与 Android 优先做麦克风录音、会议回看与问答；端侧转写按设备性能选择模型档位。
- 不要求所有手机都实时运行 large-v3-turbo，不要求手机具备与 Mac 相同的其他应用声音录制能力。
- 多端使用不等于自动同步。云同步、局域网传输和桌面协同转写需要独立设计和用户授权。

技术依据、模型规格和平台限制详见配套技术方案。

## R51 / A51 外放回声消除实验版

本场在首次录制前明确选择麦克风＋电脑声音，可独立启用AEC，默认关闭，不因AEC扩大录制音源。适用于会议声音经默认内置或USB输出设备外放；耳机无需开启，蓝牙、聚合/虚拟输出等本版旁路。降噪可关闭或按需选轻/中度，参数开录后冻结。

原轨先落盘，以同场/同录制epoch/共同主机时钟的系统原轨作为10ms播放参考。无精确时间、参考缺段/不可读、输出路由未确认或不支持时，明确使用降噪或原声旁路；参考有效并完成预热才使用AEC输出。系统原轨和原声ASR保持，不能将“算法已处理”冒充声学效果已验收。

持久化AEC处理与校准/静音/旁路覆盖、原因及APM内部延迟统计。回听/导出沿用独立增强轨，导出前显示并说明旁路；暂停、真实缺口、epoch/路由变化重置，重启重放，删除/退出保留原轨并阻止旧任务写回。真人外放/双讲、USB/睡眠/两小时仍需授权验收，详见[AP03b执行记录](./音频增强组件_AP03b验证.md)。

## R109 / A109：缺少会议依据时的经验回答（2026年10月26日）

在已有通用职责、人设四项、本场模板和本轮方式组合中加入固定经验规则。问题明确但未找到足够的相关会议依据时，可结合知识与经验给出简短建议；普通问答仍按3–10秒/10–20秒/约30秒软目标，来源开场计入时长，必要时按追问开关澄清关键条件。经验不能补造负责人、日期、金额或已确认决定；查询这些事实时先说明缺口。

经验条目使用suggestion+basis=experience且sources为空，由宿主在首次经验条目前添加来源开场。只读部分、ASR积压/缺口或历史未覆盖时使用“目前我还没找到相关讨论。根据我的知识与经验，……”；只有宿主确认本场全范围原文及历史无缺口时才可使用“前面我们还没讨论这一点”。混合回答的已读事实保留有效引用，经验部分用“这部分……”限定缺口；通用聊天只说“根据我的知识与经验”，不假装已有会议。

用户明确要求只依据本次会议/不要经验时，只回答可证实内容，缺口为unanswered，不补经验。语义限制由通用提示遵守，常见明确中文限制另由领域字面规则兜底；不新增分类模型调用。格式或引用错误单独修复，不能因校验失败自动转为经验建议；最终失败明确提示校验未通过，不称会议无上下文。文字、朗读使用同一持久化正文，关闭调试仍显示来源说明；不写入会议事实、纪要或自动执行动作。
