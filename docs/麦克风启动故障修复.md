# 麦克风启动故障修复

日期：2026年10月18日。范围：用户报告“线下：麦克风”、`npm run desktop:run`、已同意麦克风访问后出现“音源初始化失败”。暂停会议类型/对话扩展开发，仅处理此故障。

## 1 根因与证据

本机音频框架日志多次出现 `Format mismatch`，input hardware 为 1 声道 48000Hz，client format 为 1 声道 44100Hz，紧接 `Failed to create tap, config change pending!`。程序把启动后的第一个故障帧统一显示成“音源初始化失败”，隐藏了音源和原因。这不是麦克风未授权的分支。

原生代码先创建 AVAudioEngine，随后切换 CurrentDevice，却读取 inputNode.outputFormat：该值仍可能是旧聚合设备的格式。改读硬件 inputFormat 后，真实检查不再出现上述 mismatch，但启动时排队的配置通知依然触发主动停止。进一步将通知处理改为检查引擎是否仍运行、实际设备是否仍为选定 ID、硬件格式是否完全一致；只有三项都成立才忽略该通知，真实停机、设备切换/格式变化和读取失败仍是故障。

此判断依据本机日志及 Apple 对输入节点硬件格式与配置变更的定义：[AVAudioInputNode](https://developer.apple.com/documentation/avfaudio/avaudioinputnode)、[配置通知](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/avaudioengineconfigurationchange)。不通过统一改系统采样率或清除用户权限绕过应用缺陷。

## 2 修改

- tap 使用选定设备的 inputFormat；收到硬件帧后才转换为 16kHz。复制前验证帧格式，避免格式变化时错误复制缓冲。
- 健康设备上的延迟配置通知不触发中断；实际设备/格式变化保持原故障策略。
- 启动与预览区分麦克风授权、设备启动、电脑声音、转换和缓冲故障；预览未收到麦克风帧时不能报告成功。
- 增加显式 `--check-microphone` 三秒诊断，复用 UI 预览代码，主线程投递 AppKit 通知；不打开用户数据库、读取开发凭据、保存音频或启动 ASR/LLM。启动脚本透传参数。

## 3 验证边界

用户已明确允许三秒本地电平检查。只检查真实帧和电平，不保存/转写/外发声音，不创建或修改用户会议。最终检查结果补充如下；不能据短时预览宣称真实会议和双源两小时验收通过。

| 检查 | 结果 |
| --- | --- |
| `npm run verify` | 通过：TS 类型、3 项协议测试、10 项 SQL 测试、文档链接、前端生产构建 |
| `cargo test --workspace --locked`（项目工具链） | 32 项通过，含新增权限/设备/运行时错误区分回归；不采集音频 |
| `cargo fmt --all -- --check` / `cargo clippy --workspace --all-targets --locked -- -D warnings` | 最终版本均通过 |
| `npm run desktop:build` | 最终构建成功，Swift 音频桥接与 Rust 已链接；HelmMeet.app 12.42MiB |
| `codesign --verify --deep --strict` | 通过，仍为本机 ad-hoc 签名，未对外分发 |
| `npm run desktop:run -- --check-microphone` | 最终三秒真实麦克风预览通过，mic 电平峰值约 0.01627，进程正常退出并释放音源 |
| 文档检查 / `git diff --check` | 17 份文档链接检查通过；差异无空白错误 |

诊断过程第一次更改硬件格式后，检查在启动通知到达时即中断；补齐设备/格式/运行状态核对后，最终三秒检查完成。没有为了验证而忽略全部配置变更。首次受限构建因 SwiftPM 自身的嵌套沙箱失败，在允许的本机构建环境重跑成功；不是编译错误。应用控制连接不可用，因此使用同一应用 bundle 的显式诊断入口，避免更换到无关进程的权限身份。

未执行：真实会议内容的录制/转写、用户数据落盘回听、真实麦克风拔插和采样率运行中变更、蓝牙/其他设备、双音源及两小时稳定性。这些不由三秒检查代替。修复没有清除 TCC 授权或修改系统输入/输出采样率。

## 4 使用修复版

从菜单栏选择“退出”关闭旧 HelmMeet（单独关窗仍会留在后台；若正在录制先结束），然后在仓库运行 `npm run desktop:run`，选择“线下：麦克风”重新开始。也可先主动运行上述三秒检查命令。无需为本次故障重置麦克风权限；后续若有故障，界面将显示具体音源与原因。
