# 上下文预算与发言分段优化方案

2026年10月20日，R71/R72。状态：已按用户确认接入首版代码；工程和打包结果见[开发验证](./100KB预算与自然分段开发验证.md)。用户明确要求100KB预算，并要求设计减少碎片分段的方案。本文件中的参数已作为首版工程默认值接入；工程回归已执行，授权真人质量仍待验收，不当作实测最佳参数。

## 1 产品目标与现状

将单次请求的本地体积上限改为100KB，并分开管理模型token容量；会议记录按完整发言组织，持续展示识别文字，不等一个长发言结束才显示。保留当前本地原文、时间轴、引用、词库及修订能力，不额外调用文本大模型来判断每次是否换段。

当前代码事实：

- analysis::input_budget将配置token余量当UTF-8字节上限，并另外限制完整请求64KiB。32,768窗口、4,096输出预留下，实际输入上限仅25,395字节。R70已精简工具元数据和按预算分页，但尚未替换这个计量方式。
- asr::work按最长8秒的音频窗口工作，decode_with_partial保留Whisper返回的每个segment，完成后逐条写入transcript_segments。没有独立的跨ASR窗口发言段聚合层，技术片段直接成为界面记录。
- activity已有独立Silero VAD，但当前运行受自动总结开关影响，仅维护近期活动状态；尚不能直接作为持续分段、历史恢复的完整边界来源。
- 当前混合轨转写没有可靠的说话人身份；停顿能够提供发言边界候选，不能证明相邻声音来自同一个人。

## 2 双重预算：100KB与token分别计算

### 2.1 字节上限

界面统一写“单次请求上限100KB”，工程明确采用100KiB，即102,400字节，避免Kb/kB/KiB混用。

以最终实际HTTP请求JSON的UTF-8序列化大小为准，计入人设、用户问题、保留历史、工具定义、工具调用、原文/资料结果及二次转义。100KB是最高允许体积，不要求每轮填满，也不是整场录音或原文的存储上限。摘要单批原文默认10KiB等调度参数不随之自动放大。

首版采用应用级固定100KB；按模型自定义更小字节值可后续开放。旧配置追加字段或应用默认值并版本化；不改写已发布迁移，不静默放大用户原来的token窗口或重新授权历史任务。既有失败问题不自动重放。

### 2.2 模型token窗口

独立检查：预计输入tokens + 输出预留 + 安全余量 <= 配置的模型上下文tokens。当前32,768/4,096配置仍保持，安全余量暂沿用max(1,024,窗口10%)；100KB不等于100K tokens，不据此承诺任意100KB内容都能装进32K模型。

- 已适配模型：使用经模型/分词器版本匹配验证的本地tokenizer；同时计入消息格式和工具定义开销。锁定资源来源、版本及hash。不能仅凭OpenAI兼容接口或同一家厂商就认定分词器相同。
- 首先核对当前DeepSeek模型与官方分词器/聊天模板的适配。官方提供离线tokenizer，说明最终用量以API返回usage为准：[DeepSeek Token用量计算](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/)。不将某个旧版下载包未经核对套到所有DeepSeek模型。
- 未适配模型：明确标记“估算”，采用带安全余量的文本/结构估算和同模型版本usage校准；不能继续将每个UTF-8字节直接当作1 token。估算不冒称精确上界；服务端明确返回上下文过长时，进行一次有界缩减/压缩后重试。只针对确认的容量错误，不把其他400/401/网络错误都当容量问题。
- 校准只保存字节数/字符类别计数/估算tokens/实际usage等聚合量，不记录原文、密钥或音频。同一API兼容服务的不同模型/版本分别统计。

### 2.3 压缩、分页与失败

| 条件 | 拟实施行为 |
| --- | --- |
| 完整请求接近80KB，或预计token输入达到可用输入预算70% | 就当前问题整理输入：先删除重复工具结果/冗余字段，再按需调用已有Pi对话压缩、会议记忆及原文检索；有新增待压缩内容才压缩，同输入不反复调用 |
| 单条原文/资料过长 | 沿用R70的实际next_offset/next_char_offset续读及节选标记，按剩余字节和token预算中更紧的一项约束 |
| 达到100KB或预计token不能容纳 | 不发超限请求；有界分批或缩小本轮取证量，保留当前问题、关键约束、已用事实的原文和必要近期对话，明确覆盖范围 |
| 压缩服务失败/离线 | 保留原文、完整聊天、上个有效checkpoint；能容纳则用已有记忆及相关原文回答，否则明确本次上下文整理未完成，不删除历史或死循环重试 |
| 服务明确拒绝估算请求的上下文长度 | 同一问答最多一次更小输入重试；不重复接受草稿、保存待办或其他有副作用操作，不扩大资料授权，不改写原问题 |

80KB是整理输入的软阈值，100KB是体积硬阈值，二者都不是定时调用器。会议总结与会议记忆仍共用R68调度，Pi对话压缩仍按实际需要触发；本次不另开第三个后台总结任务。

## 3 发言段：底层片段、展示段落与推理窗口分开

采用三层组织：已保存音频和现有ASR推理窗口；可追溯的已确认原文片段；供界面与助手使用的发言段。

同一发言段可以跨多个8秒推理窗口。句号、逗号、一次Whisper回调或推理窗口结束，不单独触发产品段落。已确认片段继续立即落盘、计入有效文字、用于唤醒和按需取证；界面把它追加到当前段，而不是每句新建一个卡片。

底层segment_id/revision不因合段而改变。新增发言段与成员映射投影，记录段落ID、起止时间、成员顺序及各自修订、状态和封段原因。首版按已保存原文、epoch、中断和持久VAD停顿确定性重建；不另写一份易与原文漂移的文字表，段落ID由首个原片段派生。模型输入可按段组织文字并携带源片段映射，原文内容只放一次；事实引用仍恢复到宿主冻结的原segment/revision，不能只拿一个聚合段ID绕过证据校验。

## 4 自然边界与默认参数

以下是待实测的工程默认值，而非声学组件官方标准：

| 场景 | 默认行为 |
| --- | --- |
| 连续说话、换气、停顿不足0.8秒 | 持续追加当前发言段 |
| 停顿0.8至不足1.5秒 | 保持段落打开，恢复说话继续追加；标点本身不封段 |
| 连续无人声1.5至不足3秒 | 候选边界：已有完整句末，且本段至少60个有效文字或已持续15秒时择机封段；否则继续追加。必须等ASR处理追平边界前语音 |
| 连续无人声达到3秒 | 默认自然封段；下一次发言新起段，不为凑字数合并短回答 |
| 持续发言达到45秒或250个有效文字 | 标记待封段，优先选择下一处可靠句末/短停顿；续段保持关联 |
| 持续发言达到60秒或400个有效文字 | 在已确认原文边界兜底拆成续段，标记“长发言续段”；不能改写文字或冒称语义已结束 |
| 暂停、结束会议、录音epoch变化、设备断流 | 形成边界，最后尾段待ASR追平后封存；缺失区间保留，不跨缺口拼接 |
| 未来确认发言人发生变化 | 作为优先硬边界；多人同时说话保留重叠标记，不强行归给一个人 |
| VAD未知、过期或失败 | 采用长度/时长兜底，并记录降级；ASR排队或音源没有数据不能当作无人声 |

1.5秒依据有效VAD音频活动计算，不依据“多久没收到转写文字”。时间投影到排除主动暂停的录音时轴。停顿期间晚到的ASR结果仍归属其真实语音时间对应的段，不能按到达墙钟时间乱分。

短回答在明确停顿后可以独立成段，例如“同意”“先不做”；不能为凑字数把不同发言合在一起。首版只声称聚合发言段；在未接入可靠说话人识别之前，不能保证所有无停顿交接都能正确拆开。不能把同一麦克风等同同一个人，或把两次停顿之间的全部声音认定为同一说话人。

分段1.5秒软边界/3秒明显边界、助手问句默认1.2秒、总结软停顿2秒是三种不同用途的参数，不能共享一个值导致唤醒/总结行为改变。

## 5 VAD、实时体验与持久化

从writer已成功保存的所选音源派生活动元数据，始终先保存录音；复用现有组件与模型，不新增设备采集或每句大模型请求。活动检测与“启用唤醒”“自动总结”解耦；录制时根据转写分段或总结的需求启用同一worker，避免一场多建同类VAD。

双音源任一路有人声即视为讨论仍在继续；只有所有有效已选音源满足安静条件才生成自然停顿。失败/缺帧状态走unknown；在外放/自播重叠时保留标记，不能据此合并不同人的发言或删除真人双讲。复用音频主机时间/样本映射，不用ASR返回时间假造声学边界。

为分段新增有界活动区间/封段边界记录及处理水位，不能直接依赖当前worker的瞬时quiet布尔值。超出有界队列的内容明确降级；恢复时可从已保存音频局部重建缺失边界，不要求重转写全场。ASR仍使用既有单worker/context，首轮不连带改成额外高频重识别，避免引入新的负载问题。

界面保持现有逐批出字节奏：当前发言段逐步增长，尚未确认尾部以“识别中”区分；自然封段后变为稳定段落。等待1.5秒仅控制换段，不控制文字第一次显示，不增加15秒/60秒的显示等待。原始细粒度片段收在展开详情里，用于精确回听和核对。

首版人工修改从发言段展开到原始片段修订，保留已有revision流程；不把“整段编辑”静默拆回多个来源。词库归一或人工修订触发派生段投影更新，既有引用按旧修订保留并提示过期。自动总结新增字仍按底层segment/revision去重计数，不因段落追加/刷新重算。

## 6 旧会议、恢复和交付顺序

旧会议先按原有片段生成可撤销的展示分组，不改写/删除旧片段、纪要或引用。没有VAD历史时采用可靠片段间隙及长度分组，标明为历史展示分组；同一个人是否继续发言仍不能靠间隙确定。没有原音频时不能冒称完成了基于音频的重分段。按需从保存音频补算活动边界在本机进行，用户数据只读/派生，原文不重写。

| 阶段 | 交付 | 验证重点 |
| --- | --- | --- |
| P1 双重预算 | 100KB完整请求硬限、tokenizer/估算适配、统一Pi预检与一次容量降级 | 100KB边界、中文/英文/JSON转义、token更紧的配置、长输入/压缩失败/无重复操作 |
| P2 发言段与界面 | 追加发言段/来源映射、跨推理窗口连续追加、原文与引用不变 | 同一发言多句合段、实时出字、复制/搜索/回听/修订/旧引用、重启/取消/尾段 |
| P3 自然停顿 | 解耦VAD活动、持久边界与ASR水位、1.5秒及长段兜底 | 合成活动时间线、停顿/连续语音/两路交替/VAD缺失/断流/暂停；授权真人对照 |
| P4 辅助接入 | 助手按发言段取证，范围/原文映射与R68计字一致 | 短会议碎片数量与请求体积对比；整场/最近/选中范围和修订栅栏 |

先交付可追溯分组，再启用自然封段；不能只把停顿阈值接到Whisper回调上，也不能等长发言全部结束才运行ASR。说话人识别作为独立阶段，与本次预留接口衔接。两小时真实稳定性仍按用户既定要求暂缓。

## 7 验收目标

- 100KB请求边界明确，100KB与32K tokens单位不混用；不足一屏文字不因重复结构误触发低字节预算。
- 连续发言包含多个句号且只短暂停顿时，在同一产品段落增长；跨多个ASR窗口也不新建多段。
- 1.5秒自然停顿、长发言续段和中断边界按录音时间复现；短回答不为凑字数误并，未识别发言人不宣称按人准确分段。
- 不把原84条底层证据强制缩成固定几段；用测试音频实际发言边界验收，并比较展示段数、首字延迟、漏字/重复字及请求大小。
- 旧会议原文/引用不变，崩溃恢复不重复追加或漏尾；自动总结、唤醒、词库与人工修订流程回归通过。
- 先用合成/公开夹具和本机假HTTP；真人录音、既有私有音频重放及真实模型调用按当前授权范围执行，不把历史一次性授权扩为本轮录音/外发权限。


## 首版实施边界（2026年10月20日）

已实现100KiB硬限制及独立token预检、usage聚合校准；当前采用明确标注的通用估算，尚未内置模型专用tokenizer资源，不能声称精确token数。小舵问答在本机预检/服务明确容量错误时，以较小取证页重新尝试一次；保留问题、范围、历史及原文，不自动接受草稿。80KiB后停止扩大取证，优先根据已有信息回答，不专门新增一次模型压缩调用；Pi旧对话压缩仍按70%预算工作。结构化总结继续按既有有界批次处理。

停顿细化为用户确认的1.5秒候选/3秒明显边界；候选需句末且60字或15秒，短思考停顿继续追加。活动worker已与自动总结/唤醒解耦，持久化按epoch隔离的全音源停顿；ASR未追平、失效/过期不能产生有效自然封段。历史会议无VAD时仅依据时间戳分组，新录制缺少VAD时按长度/时长兜底并标unknown。长段上限在既有已确认ASR细片边界切，可能多一个确认片段的长度，不强行切开未确认文字。

界面、原稿及复制按段展示；展开后逐片修订。整段选区映射到所有原成员，工具行带paragraph_id使助手识别连续发言，事实来源仍是原segment/revision。原文细片仍会保存，减少的是展示碎片和上下文组织成本，不删除旧的84条证据。发言人识别、专用tokenizer、参数真人调优保持单列后续。

## R85修订：模型能力驱动的请求预算（2026年10月21日）

R85 将本文件中“全局100KiB硬限制”的首版参数升级为动态策略：输入预算按 `context_tokens - max_output_tokens - 10%安全余量` 计算，再以约4字节/token换算为请求体安全预算，最低128KiB、最高8MiB。8MiB仅是HTTP/JSON绝对防护，不代表模型一定能接受；模型上下文和服务端响应优先。配置允许填写最高524288输入Tokens和131072输出Tokens，输出达到 `length` 时自动扩大一次预算并重新计算输入空间。原有100KiB实现记录保留为历史验证依据，旧会议绑定和已保存数据不被静默改写。
