# 小舵全局助手开发与验证

日期：2026年10月19日。范围：R55–59 / G0–G3首版、G4保守播放参考与半双工。用户授权开发；未采集现场音频、未播放声音、未调用真实远程模型、未修改正式会议数据。以下只登记实际执行证据；真实房间效果与Intel硬件矩阵单列。

## 交付和使用

左侧“小舵助手”打开全局聊天；正在进行的会议自动成为上下文，无活动会议则通用聊天，可明确切历史会议。会议内面板共用同一会话；语音和文字混合追问、问题来源标记、引用/修订、草稿保留。通用资料在全局设置按集合版本选用，会议沿用本场资料/模型，不静默外发全库。

全局设置→小舵助手：开启“会议中语音唤醒”（默认关闭），可改中文唤醒词、停顿和播报选项。默认“小舵同学”→“小舵在”；只复用正在录制且有效的会议麦克风。按钮或Ctrl+Shift+Space说话/提交；试唤醒只检测，不发模型；无问题约5秒退出，有效语音停顿默认1.2秒提交，25秒后提示剩余时间，30秒上限。暂停/中断/结束/关麦克风/锁屏仅文字聊天；没有额外常驻麦克风。

语音问题在原ASR worker共享WhisperContext转写，然后作为source=voice、utterance_id去重的普通聊天回合调用Pi；答案同时存在聊天。TTS是macOS AVSpeechSynthesizer，缓冲合成到受控播放器；原答案前部最多120字的完整句播报，不再调用LLM改写。“停止播报”保留消息，“取消回答”终止统一回合。会议结束前已提交问题可继续完成文字，迟到语音不播。

会前自然语言准备会议、记笔记由Pi生成可见草稿，接受后Rust幂等执行；准备后仍在既有页面明确启动录音。没有自动纪要确认/外部发送/任意shell。多会议联合研究、直接自然语言录制控制、自动澄清回应窗口、英语唤醒与音色细调未交付。

## 实现证据

- Pi SDK1.3.0、Node22.22.2；stdio自定义provider、固定5工具、内存资源/会话/设置。数据库/Key/HTTP和证据校验由Rust管理。SDK运行时没有默认编码工具、扩展、宿主技能、凭据发现或任意网络。
- macOS sandbox-exec+Nodepermission实际禁止外部读、写、联网和子进程。单次8工具/2检索/6模型调用、一次修复/60秒；每次模型请求加入优先队列，问答优先下一轮自动总结；正在执行的任务不强占录制。
- SQLite v11事务迁移、升级备份、旧问答关联与历史revision回查、重启未完成回合失败；单活动回合、source/utterance去重、generation/模型/epoch取消栅栏。
- Sherpa1.13.8/ONNX Runtime1.28.2、chunk8 int8 KWS和固定SHA Silero VAD；选用模型资源约5.8MiB。语音独立worker，麦克风先持久化再try_send，队列满只使本次问题失效；跨包连续10ms组帧，原轨不变。
- 本机TTS PCM/主机时钟参考进入在线APM，不叠加系统轨；答案播放时暂停KWS并保护回声尾段。按钮打断已接，自动语音打断未启用。助手播报事件与原文重叠标歧义，禁止新助手事实引用，原始双讲仍完整保留；人工修订后可用。
- 构建资源按Rust target选择Node，避免Apple Silicon上的Intel版npm误选架构；目标独立配置，不改共享Tauri配置。Node先签名再签.app。模型/代码依赖锁、LICENSE/模型作者许可声明随资源提供。

## 唤醒后白屏与退出受阻修复（2026年10月19日）

症状：唤醒创建语音回合后页面空白，无法通过页面结束录制，原生退出也无效。实际3秒线程采样主线程仍运行事件循环，录音文件持续写入，未发现主线程死锁。原生退出被“仍在录制，请先结束会议”规则拦截；窗口关闭本来也只是隐藏，故白屏后没有可操作的结束入口。

根因：assistant::detail在空answer上使用serde_json::Value的IndexMut读取evidence，访问时意外把null改成{evidence:null}。前端的t.answer?.blocks.map只保护了answer为null的情况，无法处理缺blocks的非空对象，因而语音回合pending/running/failed/cancelled即可触发整棵React树卸载。新增合成Rust用例先复现pending返回{evidence:null}并失败，再修复为get_mut访问，通过四种状态均保持null的断言。

修复包括：后端不再制造半成品答案；前端渲染边界验证blocks/sources/evidence，并剔除不合法可选显示字段，失败仍显示原回合状态；根组件增加独立恢复页，异常时可重新加载界面或读取当前会议/version/capture_epoch后，二次确认调用既有finish_meeting，不绕过录制状态栅栏。未增加任意命令或采集权限。

现场恢复：先在应用数据目录emergency-backups/white-screen-20261019T100923Z保存一致SQLite及175个音频副本，权限0700/0600、数据库完整性及副本哈希检查通过，不复制credentials。首轮备份库只读重开失败（unable to open database file），未计为备份成功；保留该副本，重新使用DELETE journal的独立备份完成后才停止原进程。原生退出确认被录制保护拦截后，仅对已核对路径的白屏PID发送SIGTERM。没有批量终止其他进程、删除会议或重开麦克风。

停止后记录179个音频文件的长度及哈希；修复版正常启动走既有恢复链路。178个原sealed文件SHA256逐一未变，最后1个未封口文件的PCM SHA256与长度未变，WAV头修复有效；writing=0、recording=0，录制时长712300ms，本场保留interrupted供用户决定继续/结束。正式小舵会话可正常打开，原生Quit实际退出，随后重新启动成功并保留会议列表；未主动提交新问答、自动重试失败模型或启动新录音。真实界面恢复截图仅在本机临时目录，不提交仓库。

工程验证：Rust97项通过/2默认忽略；默认/无feature严格clippy及fmt通过。npm verify通过（TS9，含新增2项显示结构回归；Pi2、Python25、typecheck、33文档链接及Vite）。合成UI scenario=voice-lifecycle覆盖等待→失败、已取消、已完成及旧{evidence:null}混合历史，无白屏且控制台无error/warn；scenario=render-recovery明确注入另一渲染异常，验证恢复页、取消继续、重新确认结束及成功提示。截图voice-turn-recovery.png、render-recovery.png位于忽略的artifacts/design/duozhou。arm64修复包已构建/签名；合成PCM/本地Whisper AppKit退出idle/busy/loading为2.58/2.06/1.56秒，全join后exit0无Metal断言。Intel修复包也已完成构建/严格ad-hoc签名，Intel目标含测试严格clippy通过；未运行Intel二进制。真实重新唤醒未采集，本轮已复现并验证的是回合状态引发的渲染故障；两小时真实稳定性继续暂缓。


## 整场纪要引用范围修复（2026年10月19日）

用户报告指定会议两次整场纪要失败，错误“模型引用了输入范围以外的原文”。仅只读任务元数据：快照212段、无缺失ID/修订变化；8次播报事件与10段未人工修订原文重叠。确认原代码仍将这些重叠段作为transcript发给模型，却从known中排除，导致输入和可引用范围不一致；同时map/reduce校验沿用整场known，未细化到当前批次。失败原始模型响应没有保存，无法还原当时究竟引用了哪一段，不能把具体非法引用内容当作已确认事实。本轮未重发真实会议到模型或修改原稿。

修复：分批前排除重叠未核对段的正文，只用可引用段生成；输入快照额外保存excluded_manifest（ID/revision/reason）和citation_policy版本。每次map/reduce从实际transcript/parts构造独立引用范围，生成ref_001等短编号及allowed_evidence，历史/前次摘要只保留在本批存在的引用。返回时由宿主严格按短号＋修订映射回真实segment_id/revision后校验和写回；别批原文即便在整场manifest中也不能越界，未知ID/错修订仍拒绝，一次修复明确要求逐字复制本批编号。归并每一层重新映射，不跨请求沿用短号。预留引用清单上下文预算。

原稿和重叠真人双讲不删除，人工核对修订后可重新纳入；剩余原文正常生成incomplete草稿，coverage保留重叠段数，页面及Markdown导出明确提示“有N段与小舵播报重叠，未纳入自动生成内容”。全部原文都重叠时在本机给出需核对原稿的具体错误，不请求模型或伪造完整纪要。
