# 结构化输出与文件凭据修复

2026年10月19日 · R52/A52、R53/A53 · 本次范围：分析失败和凭据跨平台存储

## 分析失败：定位与修复

对用户本机数据库仅作只读错误类型/配置上限检查，没有输出会议标题、正文、密钥或原始模型响应：存在总结/纪要“模型结构化结果无效”、一次“事实缺少依据”和一次Keychain读取失败；当前DeepSeek配置输出上限4096。旧代码未保存finish_reason，不能据此断言这些失败都由截断引起。

已修复的具体问题：

1. 旧请求仅用提示词要求JSON。现在分析和连接测试使用`response_format: {type: json_object}`；只有服务明确返回400/422且指出不支持此参数才有一次兼容回退，仍须本地结构与证据校验。普通鉴权/限流错误不触发格式回退、不换模型或服务。
2. DeepSeek官方服务默认启用思考模式，原4096预算可能先用于推理。对`api.deepseek.com`明确发送`thinking: {type: disabled}`，适配会议总结/纪要任务；不把该厂商参数发送到其他兼容服务，不读取/展示reasoning_content为结果。
3. 读取finish_reason：length明确报输出截断并指引调整输出上限/范围；过滤、工具调用、空正文和响应超限各自报错。未闭合JSON不截取内层片段伪装成功。
4. 允许完整JSON外围的BOM、代码围栏和说明文字；多个对象、截断、类型/字段错误仍拒绝。一次结构修复用原始输入重新生成，并给出具体校验原因，不把大段坏回复再次塞入上下文。
5. 提示词示例改成完整、合法的kind/section示例；证据、负责人、日期和章节校验继续保留。任务失败不写产物；后来成功的新任务不再常驻展示旧失败。
6. “测试连接与JSON”改用固定合成文本，实际校验JSON结构和至少一条真实合成片段引用。普通OK文本不再被误认为结构化能力可用。

官方依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。上述兼容策略不代表JSON模式能保证事实正确，业务引用校验仍由本机完成。

## 凭据：文件优先，保留版本隔离

按用户本次明确要求，取代先前“正式凭据只存Keychain”的约定。默认保存在应用用户数据目录`credentials.json`，不放进`.app`、前端包、SQLite、日志或Git。macOS当前目录为`~/Library/Application Support/com.helmmeet.desktop/`；其他系统由Tauri app_data_dir决定，凭据存储层不依赖系统钥匙串。整套音频应用目前仍是macOS版本，未声称完成Windows/Linux移植。

配置格式示意（不是真实密钥）：

```json
{
  "version": 1,
  "api_keys": {
    "profile:<配置ID>:<独立凭据ID>": "由模型设置填写的密钥"
  }
}
```

- 密钥是明文，用户可备份或迁移文件；不要共享、提交或当作加密保管。macOS/Linux文件权限0600；Windows使用当前用户应用数据目录的权限继承，尚未实机验证Windows ACL。设置界面明确展示保存位置和明文性质，保存后不回显密钥。
- 唯一临时文件→写入/fsync→原子替换；进程内互斥和标准文件锁防止多实例丢更新，锁文件不含密钥。依赖已有锁定tempfile 3.27.0，不新增凭据服务。
- 格式/版本损坏拒绝读取和覆盖；拒绝凭据目标或锁文件的符号链接。单文件1MiB上限。删除/轮换沿用独立credential_ref、撤销记录、受影响会议generation及清理队列，不因同URL而合并账号。
- macOS升级只尝试一次读取旧有效凭据并转存，保持引用ID和配置版本；写入后读回核对。成功后正常请求只访问文件。旧Keychain条目保留作迁移回退，不进行自动删除；后续清理需用户自行管理。
- 旧钥匙串拒绝/缺失时录音转写继续；设置提示重新填写密钥或主动“重试配置迁移”。失败后不在每次启动反复读钥匙串，主动重试才再次尝试。文件中已有凭据不被旧条目覆盖；明确轮换/撤销的旧引用不再迁回。
- `credentials.json`、锁文件和临时文件加入Git忽略；开发`config/local.json`仍按此前授权保留、不提交。前端DTO只含凭据存在/可用状态，没有密钥或凭据引用。

## 固定结构化诊断入口

`--check-model-json`仅接受显式指定且不含旧数据库的`HELMMEET_SMOKE_ROOT`。通过开发配置初始化临时文件凭据，测试只发送程序内固定合成文本，不启动音源、Whisper或读取真实会议。返回仅为测试状态；测试目录必须安全删除，不把凭据目录作为测试产物分享。连接检查可能产生一次请求和至多一次结构修复，传输重试/格式回退仍受总次数限制。
