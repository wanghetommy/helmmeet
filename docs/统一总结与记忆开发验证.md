# 统一总结与会议记忆：开发验证

2026年10月19日至20日，R66/R68/G5首版。用户确认执行三档、首份门槛及动态停顿方案。本轮只开发与合成验证，不采集真实音频、不调用真实会议远程模型、不修改正式会议库；R67/G6语义表达校准仍为后续。

## 实现与使用

- 一个“自动总结（同步更新小舵记忆）”开关、实时/3分钟/节省三档；首份500字或3分钟且200字，后续实时(30秒且20字)或100字、3分钟且200字、节省3000字或10分钟且1000字/5分钟冷却。原文计字忽略空白标点及partial重复，修订单独重算。新会议推荐3分钟，自动开关仍由用户选择。
- 上一任务终态后建立下一窗口，失败不推进覆盖。阈值按ASR已处理的录制时间推进，软停顿截止另用录制期间单调时钟；因此ASR不再返回时也不会让已就绪任务永远等停顿。连续2秒无人声优先，最长额外等实时8秒、首份/3分钟45秒、节省60秒，新字不重置期限。立即总结/收尾可处理较短非空文本。
- activity独立有界worker从writer已成功保存的所选音源分支接收PCM，Silero VAD只计算语音活动，不启用KWS、不打开额外设备。双源都有效且安静才认为停顿；缺帧/失效unknown不算静音。唤醒关闭或仅电脑声音也能派生状态，小舵问句1200ms端点保持。
- stage产物、会议记忆索引和准确覆盖在同一SQLite事务提交；助手get_context读取有效结构化总结，不为“记住同一总结”额外发一次请求。没有新增内容的手动总结复用已有有效产物。原文、完整聊天、历史总结均保留，人工总结展示修订不反向改写事实。
- 追加0012迁移：旧minute映射three_minutes并提示，保留enabled/授权，配置版本递增，新增economy。升级前沿用一致备份/事务，索引和分片与源数据外键级联；不改旧迁移。

## 有界积压与恢复

未知模型使用UTF-8字节的保守token上界，保留输出及max(1024,10%窗口)余量；完整请求还限64KiB。摘要新原文采用动态预算40%及10KiB较小者，单段过长按Unicode字符和原segment/revision/字符区间拆分。普通原文段保持既有段边界，特大单段按字符切分，不假称强制识别了语义句末。

自动一次任务最多2个map批次加必要归并；成功事务记录summary_fragments，覆盖有洞则不标整个segment已完成，下一轮跳过已提交区间。积压达到50KiB界面提示，本机原文仍持续保存；较大积压或持久化部分分片进入追赶调度，不再等完整3/10分钟才补下一批。后台排队让位问答。失败有网络重试/30、120、300秒调度退避及共享模型后台冷却，429尊重更长Retry-After；配置错误明确暂停，成功后清理冷却。

提交前及事务内复查generation、授权、模型和任务版本；失败保留上份有效结果，重启从未覆盖区间恢复。摘要显示的覆盖水位由未覆盖原文位置推导，存在缺口时不冒称整场完整。模型服务不可达不伪造离线新回答。

## Pi对话压缩

Pi1.3.0已启用受控压缩，stream经Rust回传provider usage/finish_reason；无工具压缩请求与固定五工具问答声明分开验证，凭据与网络仍由Rust持有。SDK不能读取数据库或任意文件、开shell、联网。

宿主按范围/模型/epoch保存压缩摘要、through_turn、tokens_before及usage。旧聊天按完整问答对分页读取，每页有128KiB上限，预算预留当前问题/会议背景/工具；一次问答最多做3批旧历史压缩，超量保存进度并明确提示，不丢弃原记录。压缩后近期原话保留；重启恢复checkpoint，不再固定只取8轮。失败时若完整输入仍在硬预算内可继续原历史问答，否则保留历史并提示缩小范围。整轮问答/压缩另有总时限。

会议记忆首版读取最近有效stage的有界事实索引（8份、8KiB），原文仍可全场检索，显式recent/selection不带整场概览；摘要来源修订/模型不匹配时排除，重要事实须再取得原文。索引始终标记partial，不能据索引断言整场无遗漏。更深层主题树/长期主题检索、精确tokenizer与全自动语义校准尚未实现，不把它们混同本次首版。

## R70：会中问答读取超限修复

排查发现短会议的分段元数据也会累计占满预算：84段、原文约2KiB时，旧工具行约24KiB；人设/声明及多次分页叠加后会超过32768窗口、4096输出预留下的25395字节保守界限。该异常发生在HTTP发送前，本轮只在本机读取聚合长度，不外发正式原文。

修复将重复UUID保留在Rust，模型端只携带source_id及必要字段。工具结果按当前已发消息、待回复工具调用、工具声明及JSON双层转义精确预算，按剩余轮数预留协议空间。最多24段且按实际next_offset推进，单段超长提供char_offset/next_char_offset；部分来源不计为完整段覆盖，未返回行不登记为可引用依据。get_context按预算保留范围/授权/水位和部分背景，明确partial；搜索结果仍不代表全场完整扫描。Pi原有对话压缩、源文/历史保存规则不变，不用虚增模型窗口或删除旧记录解决问题。

新增离线假HTTP回归：84段、32768窗口、4096输出预留，get_context加四页原文再回答，每次完整请求均≤25395字节，84段已读覆盖且完整本机来源保留。长单段混合中文/引号/反斜杠/换行按1800字节线传预算逐片还原，验证Unicode无丢字/无跳段与未返回笔记不能引用。工程与交付最终结果见验证记录；不把假HTTP当真实模型主观质量通过。
