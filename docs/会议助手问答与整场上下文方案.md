# 会议助手问答与整场上下文方案

2026年10月20日。状态：首版运行逻辑已接入，真实模型语义和实机会话仍待验收。本方案结合“检索已达上限”、此前模型调用上限、总结分类失败和覆盖提示，统一设计问答；不以增加上限作为主要修复手段。

## 1. 当前问题与产品目标

当前代码中，search_evidence每轮最多两次，第三次直接使问答失败；另有八次工具、六次模型调用和运行超时限制。这些是应用内部保护，不是DeepSeek账号限额。本轮未重放正式“测试会议”，没有确认其第三次搜索的具体内容。

现有会议记忆取最近最多八份有效stage产物，事实索引最多8192字节，不保证整场完整；get_context、原文检索均主要依赖Agent自行调用。检索按字符二元组匹配、最多取十条，缺少完整发言邻文和跨主题覆盖。由Agent反复读取背景、试探关键词、逐页翻原文，容易在回答前耗尽次数。

目标：小舵默认了解当前会议从开始到已确认转写终点的全局脉络，结合最新讨论回答当前目的；具体事实可查原文，允许使用大模型的常识和专业判断，缺少关键条件时自然反问。语音和文字共用上下文、同一答案和聊天记录。会议中尚未转写的声音不视为已知，用户明确选定局部范围时不得扩大。

“整场可检索”“每段原文已处理”“所有细节都保留在摘要中”是不同概念。即使处理覆盖完整，摘要仍会压缩细节；不能只因摘要没写就断言会议没提到。

## 2. 回答前自动准备上下文

由Rust宿主准备ContextPack，不再要求模型先调用工具才能知道会议背景。准备过程优先本机读取和检索，不额外调用模型做问题分类。

固定输入包括本次问题、第一人称会议专家人设、会议目标/议程/类型、授权范围、必要用户记录和聊天记忆。会议原文只读取本场final/edited版本。为当前回合冻结generation、模型版本、资料版本和转写水位；后续录音进入下一回合，修订/撤销授权仍使旧回合失效。

| 状态              | 自动放入模型的会议背景                   | 补充策略                     |
| --------------- | ----------------------------- | ------------------------ |
| 整场原文可以容纳        | 全部已确认原文，已有总结作短导读              | 不搜索、不翻页即可回答；不重复发送同一原文    |
| 长会议且记忆有效        | 覆盖较早讨论的累计会议记忆＋记忆后最新原文＋与问题相关原文 | 必要时允许补充检索                |
| 无总结或总结失败，原文可以容纳 | 全部已确认原文                       | 不要求先总结，不因自动总结暂停而禁止问答     |
| 无有效记忆且原文过长      | 本机按整场主题/时间索引选取背景、最新原文和相关原文    | 标明全局背景尚未整理完整；整场审阅走有界分批任务 |
| 记忆落后且未覆盖原文过多    | 仍有效的旧记忆、最新原文、未覆盖范围内相关原文       | 后台按既有总结队列补齐，不能默默丢弃中间积压   |

“可以容纳”按实际完整请求判断，不能按会议时长或原文条数判断。预置原文和记录也须注册为本轮已提供来源；引用校验不能仍只认可工具返回的来源。

## 3. 两种记忆，各管一件事

会议记忆保存：会议目标及变化、主要议题、已确认决定、方案及依据、分歧与风险、未决问题、明确行动、关键实体和必要数字。每项关联原文修订和时间范围，保留“最初提议→后来否决/调整→当前状态”；不能把提议升级为决定，不能用旧摘要覆盖较新改口。

会议记忆包含：跨整场的简明概览、可按议题读取的主题记忆、原文来源索引。近期总结不能挤掉会议开头的重要目标。主题记忆超出预算时做有界分层归并并缓存，不能无限把上轮摘要再次摘要，也不能无提示仅保留最后八份。

Pi聊天记忆保存：用户和小舵已澄清的目标、偏好、追问、已经接受的记录及未决事项。保留最近完整问答，更早部分沿用已接入的Pi压缩与宿主持久化。聊天历史中的回答不能当作会议事实。

语义记忆须由模型生成；本地只能完成索引、去重、来源/修订校验和拼装。不能宣称本地字符串拼接已实现可靠的整场语义理解。

## 4. 复用总结更新记忆，减少调用

沿用已确认的统一自动总结周期，不另加一套按唤醒次数触发的记忆定时器。同一次总结分析产生展示内容和可复用的结构化事实；宿主维护主题索引和覆盖清单，不对相同内容再调用一次模型生成记忆。

短期修复不依赖重新生成所有历史总结。已有有效产物先校验来源并构建索引；不足以覆盖整场的部分明确登记为待补齐。历史重建、长会议主题归并和大量积压处理复用本场授权及串行分析队列，不在每次问答前重复执行，不绕过全局暂停或本场关闭决定。

首份500字或3分钟且至少200字、实时/3分钟/节省调用三档、停顿条件等保持现有确认参数。升级不自动恢复已暂停的远程任务；无总结仍可在现有问答授权范围内读取原文。

## 5. 相关原文检索

第一版使用轻量本地检索，暂不引入额外向量模型、常驻进程或大体积依赖。中文分词/字符词组索引配合BM25类排序，本场词库辅助人名、术语和别名匹配；同义问题按可审计规则扩展。后续通过实际命中率决定是否增加语义向量检索。

检索以发言段/主题作为返回组织单位，底层segment_id/revision仍是证据。命中后补前后相关发言，保留原文顺序；将“是否、还没、建议、否决”等限定与改口一并提供。时间先后和最新修订用于处理冲突，不把只匹配关键词的一句话当完整结论。

问题原文、最近追问指代、会议目标和术语共同参与本机首轮检索。会议、资料、用户笔记/待办分别排序和标注，不让管理方法文本挤掉会议事实。检索结果按内容/来源去重并受字节与token双预算约束，而非固定十条。

## 6. 普通问答与整场审阅分开调度

普通问答默认一次模型回答。宿主已提供上下文；模型确有依据缺口时允许至多两轮补充检索批次，一批可含受限的多个关键词或精确来源ID。原文按ID回查是来源核对，不应和同义词试搜共用机械的“两次搜索”计数；各自仍有返回容量和总工具预算。

本机首轮检索不消耗模型调用，但仍受检索工作量、时间和返回容量限制。完全相同的查询、范围、版本和游标命中缓存，不重复读同一页；新版本不能误用旧缓存。Agent不再为读齐整场背景执行串行翻页。

“检查整场所有目标/全部决定/是否有遗漏”需要整场审阅，不能等同于相关性Top-K搜索。如果完整原文可容纳则直接审阅；否则读取覆盖全时间范围的有效记忆及所需主题原文。涉及穷尽性列举且现有摘要不足时，生成可取消、有进度的分批审阅任务，冻结截至当前的范围，有界分析并归并、保存检查点，下次可复用；不塞进普通问答的六次循环，也不冒称后台任务可无限调用。

整场审阅的批数、用量和截止时间应在任务启动前按原文量估算；仍超过预算则分阶段交付并说明范围。保持既有外发授权和暂停规则，不借自动升级跨会议或扩大资料范围。

## 7. 额度用完应收尾，不应直接报错

保留普通问答单轮六次模型调用作为首版成本上限，目标通常一次、复杂问题二至三次；显式区分回答、补充规划、聊天压缩及格式修复的消耗。预算统一由宿主分配，不能Pi侧和Rust侧各自计数造成冲突。至少保留最终回答及一次格式修复名额，压缩或搜索规划不能占用最后的回答名额；无法容纳的历史提前压缩并缓存。

工具总数先保留有界保护，但次数用完时返回结构化retrieval_exhausted并关闭后续检索，模型依据已提供内容回答或提出一个具体澄清问题。不得用Err直接销毁已有上下文。若同一模型响应含多个工具调用，须为所有tool_call_id返回配对结果，然后进入无工具回答，不能中断协议。

缓存重复查询，连续无新增证据时提前收尾。达到搜索/工具额度与实际服务故障区别处理：前者尽力回答；后者保留问题和输入快照、明确失败，禁止本地伪造模型答案。最终回答仍请求工具、无效引用或修复后仍不合规时明确失败，不为降低报错率绕过校验。

100KiB硬上限保持；完整JSON、人设、历史、工具和结果转义都计入，同时受所选模型token窗口/输出预留限制。初始上下文以80KiB软线及token剩余量共同控制，留出后续工具协议空间；不能把80KiB必然解释成所有模型都能接收。优先保留问题、授权范围、关键记忆和相关原文，先裁重复工具历史、不相关资料和可压缩旧聊天；不静默裁掉会议早期背景。

普通问答的超时和后台审阅各有独立、用户可取消的截止时间；网络及队列等待须可见。不存在靠放宽六次上限就保证每场会议完整回答的方案。

## 8. 事实、判断与反问

- 会议事实：使用当前原文或经来源校验的会议记忆。记忆可以提供背景和概括；涉及具体承诺、数字、人名、时间、否定或冲突时自动补原文。记忆来源若未能在预算内核实，不据此编造直接原文引用。
- 专业建议：允许大模型提供常识、5Why/目标/项目管理判断，不强制伪造会议引用；用第一人称自然说明“我建议”“我的判断是”，不声称这是会上决定。
- 资料与用户记录：明确是资料说明或用户保存内容，不升级为会上共识。
- 关键条件缺失：先回答已知部分，再问一个最影响判断的问题。检索没命中不等于会议没说过；未完整核对时用“我目前没有找到明确记录”，不用“整场从未提到”。

正文不机械朗读分类，不展示内部分析、搜索词、调用次数和技术ID；屏幕保留可点来源。语音播放同一回答，短播报的截取不能改变原结论。

## 9. 覆盖展示

用三种独立状态替代统一的“覆盖不完整”：

1. 转写进度：录音截至时间、已确认原文截至时间、实际缺失/失败区间。
2. 记忆处理进度：原文处理清单及修订、累计记忆覆盖范围、待处理量和失败原因。最大时间戳不能代表中间无遗漏；“全部处理”不代表所有细节都保留在摘要。
3. 本轮回答依据：整场原文、整场概览＋相关原文、或部分范围；来源和必要限制可展开，默认不给完整回答加大段免责声明。

播报重叠是单独待核对项，不能把所有此类片段永远当成会议缺失，也不能直接取消现有防自播污染保护。纯助手声音和真人双讲需分别处理，无法确认时保留原文并标记；不把本次问答改造扩展成未经验证的音频来源识别实现。

| 阶段 | 交付                               | 核心验收                                                 |
| -- | -------------------------------- | ---------------------------------------------------- |
| P0 | 检索额度耗尽改收尾、查询去重、统一计数与保留回答额度       | 第三次搜索/第九次工具请求不导致整轮直接失败；所有待返回工具ID配对；已读证据仍可回答，未知引用仍拒绝  |

| P2 | 累计概览＋主题记忆＋完整覆盖清单，复用总结队列          | 开头目标不被后续更新挤掉；中途改口覆盖旧提议；失败/断网/修订保留未处理区间，重启可续，不重复同内容调用 |

## 11. 首版实施结果（2026年10月20日）

本轮已将方案的 P0–P3 首版接入现有问答链路：

- Rust 宿主按回合统一模型预算，搜索和工具额度耗尽返回结构化收尾结果；保留最终回答与一次结构修复名额，并为多工具调用逐个返回 `tool_call_id` 配对结果。
- 每轮首次模型请求前生成冻结 ContextPack。短会议可直接带入全部已确认原文；长会议带入累计会议记忆、用户已保存记录、早晚锚点和相关原文。记录仍标为 `user_record`，不能当作会议事实。
- 轻量本机检索增加中文字符词组、术语别名、BM25 类排序、段落邻文和精确来源回查；不引入向量模型或常驻网络服务。
- 整场审阅走独立的有界分批队列，批次结果按会话、generation、授权、模型和问题缓存；保存进度后可继续，普通问答不承担整场翻页。
- 回答覆盖现在分别报告转写水位、原文返回范围、记忆处理量、缺失区间、播报重叠和整场审阅进度；会议助手面板提供“整场审阅”入口。

对应代码为 `assistant.rs`、`assistant_context.rs`、`memory.rs`、`review.rs`、`meeting-core/retrieval.rs` 和 `meeting-core/budget.rs`。迁移沿用现有版本链，未删除原文、聊天或历史来源。合成假 HTTP 的 Rust 全量回归已在允许本机 sandbox 的环境通过；真实模型回答质量仍由用户另行验收，不将合成测试当作真实会议结论。
