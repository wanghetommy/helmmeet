# 会议工作区与自动总结优化方案

版本：V0.4 · 日期：2026年10月18日 · 状态：基础实现已接入，真实会议质量与性能待验收

## 1 结论与现状

采用“会议记录 + 会议总结 / 会议纪要 / 会议助手”的工作区。原稿是转写材料，总结帮助会中理解讨论脉络，纪要是按会议类型整理的正式草稿，助手承接提问和 review。三者共享原文证据与本场配置，各自保存产物、版本和任务状态。

原有 UI 混合 stage/minutes，自动分析使用旧间隔。本轮已按以下方案接入原稿、独立三标签和完成后窗口；实际实现、自动化证据及未验收范围见[工作区开发验证](./工作区开发验证.md)。

## 2 页面结构

```text
会议名称 · 会议类型/模板 · 录制状态/时长 · 音源 · 暂停/结束
本场文本模型/授权状态                         本场分析设置
┌──────────────────────┬────────────────────────────────┐
│ 会议记录              │ 会议总结 | 会议纪要 | 会议助手    │
│ 实时记录 | 对话原稿    │                                │
│ 搜索 / 原稿版本 / 复制 │ 当前标签的正文、工具与任务状态    │
│                      │                                │
│ 原文 / 回听 / 修订     │ 事实与建议分列，引用可定位左侧     │
│ 手工笔记              │                                │
└──────────────────────┴────────────────────────────────┘
回听播放器
```

左侧导航中的模板管理命名为“会议模板”，右侧“会议助手”专指本场对话，避免同名。窄窗口上下排列、记录区可收起，右侧仍保持三个标签；录制控制固定可见。切换标签保留各自滚动位置、原稿来源、纪要选定版本及未发送问题，不清空或混用另一会议状态。

录制 A 时查看 B，顶部显示活动采集 A，正文标明查看 B，暂停/结束显式指向 A；复制、总结、纪要和对话均绑定用户操作时的会议。加载、取消和错误按模块/任务展示，不能用整个页面的 busy 遮罩阻止录制控制或原文阅读。

## 3 优化一：会议记录与原稿复制

“实时记录”保留时间分段、最新识别预览、回到最新、修订、回听和围绕片段提问。用户向上阅读时不强制滚动；partial 标识为识别中。

“对话原稿”连续排版整场已确认转写，不经大模型改写，提供以下来源切换：

| 来源 | 内容 | 展示规则 |
| --- | --- | --- |
| 当前修订版（默认） | 每段当前 final/edited revision | 显著标注“含人工修订”，便于复制校正后的文本 |
| 原始识别版 | 每段首次已保存的 ASR revision | 明确标注“原始识别”；没有该版本的人工创建片段标为无识别原版，不能伪装成 ASR |

不把“原稿”解释成准确无误的人工逐字稿。说话人未知时不编造姓名；手工笔记单独展示，不混入发言。可开启/关闭时间戳，默认开启。两种来源均支持一键“复制全文”，旁边明确来源及截至时间；可提供“复制选中内容”次级入口。

复制规则：

- 复制点击时冻结的本场、来源、片段/修订列表及排序；新转写或修订不混入同一份文本。默认只复制已确认正文和时间戳，不包含 partial、按钮、总结、纪要、笔记或回听内容。
- 搜索只过滤显示，不改变“复制全文”的范围；选中范围复制另有明确标识。没有文字时禁用，不能复制空串后提示成功。
- 复制和导出复用后端文本快照/格式化规则，不从虚拟列表或 DOM 抓取，避免只复制屏幕内片段。按时间、稳定片段 ID 排序，保持版本归属。
- 用户点击后通过受限剪贴板写入接口执行，只写入用户所选文本，不读取系统剪贴板。前端不获得任意文件或 shell 权限；开发时验证目标 WebView/平台权限与长文本行为。
- 复制成功显示“已复制〈会议名〉当前修订版，截至 XX:XX”；失败保留文本并提供重试或 TXT 导出，不伪报成功。快速切换会议后返回的结果仍标原操作会议，不能提示成复制了新会议。

首版只提供纯文本复制；富文本格式、Word 排版不在此次范围。原稿查看、复制、修订与回听均不需要启用大模型。

## 4 优化二：三个分析标签

| 标签 | 用户目的 | 主要内容与操作 |
| --- | --- | --- |
| 会议总结 | 当前在讨论什么，讨论的逻辑框架是什么 | 当前主题、讨论脉络、关键进展、分歧/未决；立即总结、自动总结、历史更新 |
| 会议纪要 | 把讨论整理成可核对、可交付的记录 | 会议类型/模板预览、生成草稿、人工编辑、版本、复制/导出；子标签“纪要正文 / 行动事项” |
| 会议助手 | 围绕本场提问、追问、review | 持续对话、范围选择、类型化快捷问题、事实/风险/建议与引用 |

### 4.1 会议总结：当前主题与讨论脉络

当前版本优先展示一张持续更新的总结卡：一句话当前主题；“目标 → 问题 → 方案/观点 → 依据/分歧 → 结论或待明确”的可折叠提纲；本轮新增进展；未决问题。没有实际出现的环节不填充假内容。提纲是“助手归纳的讨论结构”，不是模型内部推理链，推测的关联与原文明示的关系区分标注。

主视图不按十五秒刷成长聊天列表。旧快照在“更新历史”查看，每个版本保留截至时间、输入覆盖、模板/模型来源和原文引用；新结果校验成功后才替换当前机器版，生成中保留旧内容并显示进度。覆盖不足、原文已改、ASR 积压分别提示。

首版不直接编辑自动总结正文；可复制或另存笔记。已有人工编辑的 stage 版本保留可查看，不被新机器版覆盖。人工修改正式纪要在纪要标签完成。

### 4.2 会议纪要：按类型生成

沿用[会议类型方案](./会议类型与对话助手方案.md)：周会突出进展/阻塞/下期安排，方案评审突出方案权衡/风险/验证/通过条件，决策会突出选项/标准/决策状态/责任与条件，复盘和头脑风暴使用各自结构。顶部显示本场类型、模板版本和模型，不把生成时刻的全局默认当作历史来源。

会中点击生成的是“截至当前的纪要草稿”；会后在尾段转写完成后生成整场草稿，覆盖不足仍明确标记。只读取阶段总结不能宣称已经核对整场；全文/分批处理及证据校验沿用现有原则。人工修改生成新版本，自动结果不能覆盖人工版本。

下一扩展版本默认手动生成纪要，不把“自动总结已关闭”理解成仍可自动生成纪要。若保留结束后自动生成能力，必须有独立、显式开启的选项；首版可以只交付手动入口。待办仍是共享的 action_items 候选及人工确认状态，在“行动事项”里随时可看，不要求先生成一份最终纪要。总结/助手可链接到这里，不复制出三套待办。

### 4.3 会议助手：问答与 review

按本场类型及阶段推荐问题，例如“目前有哪些目标未澄清”“评审还缺什么验证”“哪些决定其实尚未成立”。基础持续对话和证据规则按原 T02 方案执行；Pi 是否采用不阻塞页面优化。Review 是基于原文的检查与建议，不是已确认的会议结论；没有证据的负责人/日期仍待确认。

## 5 自动总结：实时 / 1 分钟 / 3 分钟

设置移到“会议总结”标签，名称为“自动总结”。独立开关控制是否开启，开启后只有“实时、1 分钟、3 分钟”三档；保留“立即总结”。本场模型/授权在独立“本场分析设置”管理，不再把频率藏在模型选择弹窗中。新会议自动总结默认关闭；用户主动开启时显示目标服务及可能增加的调用量，已授权同一范围无需每轮重复确认。

| 模式 | 下一轮触发条件（必须有未总结的已确认文字或有效修订） |
| --- | --- |
| 实时 | 本轮新增约 60 个非空白文字字符，或计时达到 15 秒，先到者触发 |
| 1 分钟 | 计时达到 60 秒 |
| 3 分钟 | 计时达到 180 秒 |

60 字/15 秒是初始待验证参数，不是响应时延承诺；可在后续高级设置调整。计时使用单调时钟，只累计录制运行时间，暂停冻结；没有新文字不发空请求。计数由后端按去重后的已确认 segment/revision 计算，不计 partial、重复通知和全文累计长度。短而重要的发言也可由时间条件触发，不设置一律丢弃短句的门槛。

字数和时间是“或”，不需要两个条件同时满足。验收例：8 秒已到 60 字则当时触发；15 秒只有 20 字也触发；14 秒 59 字则继续等待。时间从本轮已确认文字窗口计算，不从声音开始时承诺十五秒返回。

### 5.1 完成后重新计算，等待期间不丢文字

一次自动总结是完整业务任务，包括排队、实际派发、必要分批/修复、校验与提交。必须等它到达终态，才启动下一轮窗口；不能收到首段流式文字或首个 HTTP 返回就开始下一轮。每场最多一个自动总结任务和一个合并的“有新内容”标记，不按每十五秒累计请求队列。

维护两个独立状态：成功总结已经覆盖的原文修订集合，以及下一轮的计时/字数窗口。

1. 首次启用从第一条尚未总结的已确认文字开始窗口；字数或时间满足时申请调度。
2. 等待/生成中仍持续接收转写，只更新未总结集合；不启动新的自动任务。实际获得调度许可时冻结最新输入快照，避免排队前的旧快照漏掉已到达文字。
3. 成功提交后，仅把本次真实处理的快照并入覆盖；生成期间到达的文字仍未覆盖。
4. 返回时已有积压，从返回时开启新窗口；没有积压，等第一条新确认文字再开始计时。计时和“返回后新增字数”从零计算。等待期间积累的文字不直接令新任务瞬间触发；它们进入下一任务输入。有积压而后续无人说话时，仍会在新窗口的时间上限触发，不能因为没有新事件而永远漏算。

例：00:07 达到字数触发，00:25 完成；00:07–00:25 到达的文字保留。下一轮从 00:25 计时；若之后没有达到 60 字，则在约 00:40 触发，并包含所有尚未总结文字。若已暂停，剩余时间等恢复录制后继续。这个设计落实“上次回来后再计算”，同时保留等待期间的内容。

### 5.2 失败、手工任务和生命周期

- 全局默认仍限制模型并发，优先派发用户问答/review、手工纪要/总结，再派发自动总结；不自动打断正在执行的任务，用户可显式取消。自动意图只保留一个，不能用第二把模型许可锁形成重入死锁。
- 失败不推进成功覆盖。网络有限重试、结构修复和退避计入当前任务预算，不是新的周期；失败后至少等待当前模式的一轮时间和必要退避，再允许自动尝试。认证/授权/凭据失效、模型不存在等不可重试配置错误立即暂停；其他连续三个业务任务失败暂停自动总结并提示手动恢复。用户取消和配置失效不计为服务失败；“取消本次”后也等待新窗口，不能立刻重提同一任务。
- 手工“立即总结”合并同范围待执行意图；已有总结在途时不重复提交，显示正在处理及取消入口。成功的全范围手工总结更新共享总结覆盖并重开窗口；问答/纪要不冒充总结覆盖。
- 切换频率、关闭自动或用户取消自动任务时，独立 schedule_version/自动任务代次使旧自动结果失效；不撤销整场模型授权，不取消无关的手工问答/纪要。关闭模型分析、换模型/模板、删除和退出仍遵循已有授权与 generation 栅栏。
- 暂停后不新派发自动任务，在途可正常完成并保留来源；恢复时接续剩余窗口。结束录制后停止周期，若自动总结已开启且有残余，尾段处理完成后最多补一轮最终总结；转写失败则标覆盖不足，不无限轮询生成。纪要是否生成独立决定。
- 重启不重放旧定时积欠或自动补发历史会议。恢复录制后从新窗口开始；保存的覆盖/失败状态可恢复。后台调度绑定活动录制及明确的尾段任务，不随当前可见页面切换。

### 5.3 上下文与成本

实时每轮不重发整场全文。以未总结文字、上一份已校验总结、相关旧事实的原文证据和本场背景更新讨论脉络；上一总结帮助索引，不能成为自证事实来源。启用时明确这一 summary_context 外发范围，旧授权不足则通过本场授权入口确认，不能把旧聊天历史一并发送。模型切换本身不触发历史补发，沿用已有目标/版本/范围授权规则。当前总结保持简短（初始建议约 300–600 中文字、最多三级提纲），历史主题可折叠，引用可追溯。上下文不足则拆分/标部分覆盖，不假装已经理清全部会议。

覆盖采用片段及修订集合/清单，不只用“最后时间戳”；人工改文会使相关旧总结过期，需要核对受影响原文。任务键包含输入快照、策略/模板/模型版本；重试沿用原键。输入记录引用规范快照，避免十五秒一轮把整场正文重复持久化造成平方级增长。

界面展示“已总结截至 / 新内容待处理 / 排队 / 生成 / 失败暂停”，不显示有保证的十五秒倒计时。实际更新延迟包括 ASR 确认、触发窗口、排队、模型生成及入库，开发时分别测量。频率只影响文本分析，不能增加 Whisper 重复推理或阻塞音频保存。

## 6 数据与兼容

追加 summary_schedules（meeting_id、enabled、mode、策略参数、version、自动代次）、summary_checkpoints（成功覆盖、失败次数/暂停原因）、summary_runs 的输入/输出关联。运行期使用单调时钟，不能把进程内 Instant 持久化；重启清零时间窗口，不变更成功覆盖。已有 stage/minutes/answer 仍分类型保存，使用各自版本选择状态；旧人工产物保持可读。具体复用现有 jobs/artifacts 表还是新关系表在迁移实现时确定，不能改写已发布迁移。

旧 interval=0 保留关闭；3 分钟映射 interval_180s；已有 5/10 分钟按 legacy 设置继续，界面说明“当前沿用旧间隔，选择新档后生效”，不在新三档里静默选实时/1/3 分钟。选新档后才迁移新策略。旧的模型授权不因升级扩大为持续聊天历史，频率修改也不自动启用分析。

复制使用 read_transcript_snapshot / copy_transcript 受限业务接口，参数含本场、来源、明确范围、时间戳选项；快照返回片段/修订清单、截至时间和内容 hash。剪贴板接口只接受受控快照与用户写入意图，不开放通用系统访问。自动调度使用独立 set_summary_schedule，模型配置切换接口中的旧 interval_minutes 逐步成为兼容字段。

## 9 本轮实现映射

- `summary_schedules` 保存独立开关、三档/旧档、代次、失败与退避；`summary_coverage` 保存成功片段修订。复用 `analysis_jobs`、`analysis_origins` 和 artifacts 的覆盖 manifest，无独立重复的 summary_runs 全文副本。
- 后台每 250ms 检查活动采集/明确尾段的轻量元数据和未覆盖修订；不扫描全部历史正文，也不由 UI 轮询触发模型。窗口使用单调时钟，暂停不增加活动时长；重启保留覆盖、清空窗口并关闭旧尾段补发。
- 派发许可为统一优先队列加单个模型许可；获得许可后冻结输入，问答优先于手动总结/纪要，再到自动总结。自动任务最多 180 秒、4 个分批/归并组；手动任务最多 900 秒、24 组，每组至多一次结构修复，每次 HTTP 最多三次尝试，均在总时限内。较长 Retry-After 直接交由业务退避，避免提前重试。
