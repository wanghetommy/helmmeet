# 音频连续性修复验证

日期：2026年10月19日 · 对应 R44 / A44 / TC-44 / J01

## 问题与边界

用户报告断续爆音、咔哒声，并确认导出 WAV 也有。本轮修复两个确定的软件缺陷：双轨混音遇一路缺失时另一条增益突变；回听每 30 秒重建播放器导致接缝。

原分轨不重写，历史混音回听/重新导出会采用新的固定增益。已经导出的旧 WAV 不自动改写。播放器改为同一 AudioContext、相邻 PCM 缓冲按精确样本时长接续，预取有限分段；切会议/拖动取消旧请求，暂停有短增益过渡，超时明确暂停。播放器音量不影响原文件。

## 已执行的定位

- 对最近录音前 16 个已封口片段作本机只读波形统计（约 64 秒）：为麦克风单轨，没有削波样本、没有元数据时间洞、样本数与时间一致，也未发现 ≥1ms 的连续零段。不读取转写，不播放、不新录音、不联网；未修改用户数据。
- 上述有限检查不能证明整段没有杂音，也不能把双轨缺陷当作该麦克风单轨问题的完整根因。原始麦克风/设备路径的咔哒声仍需针对实际出现位置复验。
- 新增合成 440Hz 持续波 + 缺失系统包回归，旧实现失败：另一轨从约 0.3 突增至约 0.6；固定增益后通过，单轨保持原幅度。
- 新增 PCM 播放测试：30 秒缓冲在同一音频时钟精确接续；旧会议迟到响应不会播放；数据未及时准备会显式停止而非隐含接缝。

## 2026年10月19日：指定两场录音后的原生根因修复

### 实录定位

用户指定“会议测试”03秒起、“AI转型讨论会”02秒起持续出现咔哒声。只读检查实际数据库及原始WAV，分别为约19.004秒/81.500秒的麦克风单轨，均非双源混音。没有读取或外发会议文字、播放用户录音或启动新录制。原文件未改写。

两段独立录音在相同采样位置出现明显突变，例如3.997秒处的相邻样本，AI录音从-4038跳到-13597，测试录音从-674跳到-183（16bit PCM）。波形检查显示突变并非仅在4秒文件边界，集中于约100ms转换包内。这支持继续检查转换器及池复用，不能仅凭大差分判定所有语音瞬态都是噪声。

### 确定缺陷与修复

旧deliver把完整池缓冲直接返回给AVAudioConverter输入块，未遵循其实际请求帧数；deliver返回后立即把缓冲交还LIFO池。转换器可能仍在读取该输入剩余区域，下一包改写同一内存会污染尚未完成的转换。已有每包新建缓冲测试无法覆盖该条件，包内跳变也可能避开仅检查输出包首尾的断言。

新增模拟实际池行为的回归：44.1/48kHz连续997Hz合成音，100ms/2048/511帧分包，反复改写同一个输入缓冲，与单次提供整段输入的转换结果逐样本比较。修复前100ms分包的最大绝对误差分别为0.5180757/0.5029535（信号幅度0.3），断言失败；不用复用池时公共前缀一致。

修复新增PacketConverter：按输入块实际请求帧数复制到独立loan；保留最后loan到转换器下一次索取输入；输出缓冲满时继续转换排空，不把未消费的池内存带回下一包。各音源独立保持转换器状态，转换失败仍通过原有源故障通道上报。修复后8种采样率/通道/交错组合×3种分包的公共前缀最大误差实测为0.0；有限转换尾延迟允许小于128个输出样本，不将它伪装成丢包补零。
