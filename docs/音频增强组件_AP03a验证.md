# 音频增强组件 AP03a / AP05a 降噪首版

日期：2026年10月19日。范围：R50独立麦克风NS实验版；默认关闭，AEC/AGC未启用，ASR仍用原声。AP04a真人音质、完整AP05设备与两小时验收未完成。咔哒声缺陷已由用户确认修复，本次不宣称修复或还原历史错误波形。

## 使用

1. 设置 → 语音增强：可改新会议默认值，旧会不变。
2. 新建会议，录制前选关闭/轻度/中度。只有麦克风轨会增强；仅电脑声音无需此选项。开始后强度冻结。
3. 原轨先落盘，处理进度显示已处理/麦克风源时长。源文件约4秒密封；增强还需后续帧排空，回听通常晚一个源片段可用，不是声卡实时输出。
4. 回听音轨可选原声/增强。未完成区间明确提示，不把原声偷偷混进增强；原声可随时使用。
5. 结束且增强完成后，“导出 / 管理”可选增强混音或增强麦克风WAV。混音的系统声音保留原声。
6. 派生失败显示错误，可释放磁盘/处理源文件故障后重试。重启会重放滤波状态、续算缺失派生文件，原轨不改。

历史会议不自动处理，首版也不开放给已开始会议改配方或历史批量生成。增强16kHz PCM16额外约109.9MiB/麦克风小时。默认构建已含APM，当前机器缓存已准备；新机器准备命令见[组件说明](../native/audio-processing/README.md)。正式默认需真人质量数据后决定。

## 工程实现

- 追加0008迁移，SQLite v8；已有数据库升级前备份before-migration.sqlite，事务迁移，复合外键/源类型/样本数约束及开录后参数冻结触发器。
- 单独Worker只读已密封原轨，一次处理一片；单片读取，有界输入/输出缓存加不足160样本输入尾部，只有一个APM实例，不让采集等待DSP或模型。
- 160样本/10ms连续组帧；固定16kHz配方NS重叠96样本=6ms，起始丢弃和结束内部排空补偿。输出与源样本数相同；缺口不写伪造归档样本。脉冲测试验证峰值回到原始位置。
- 跨文件延续状态，真实间隙、暂停epoch、麦克风关闭后重置；重启从头逐文件重放状态，已登记派生文件不覆盖。长会议重启可能等待重放完成。
- 派生文件先sync，提交事务检查本场、任务代次及删除状态。失败/删除/退出不改变原轨；暂存文件启动时清理。系统轨及原声ASR输入不改。
- 增强回听仅允许已完成区间；整场导出要求停止且派生完整。前端冻结音轨与回听终点，变更音轨/切会增加取消代次；导出按8秒块，失败清理临时输出。
- 引擎固定webrtc-apm-2.1/ns16k-delay96-v1；现有C ABI/依赖/许可沿用AP02。无通用多算法版本编辑界面。
