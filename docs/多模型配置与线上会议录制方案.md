# 多模型配置与线上会议录制方案

版本：V0.2 · 日期：2026年10月18日 · 状态：N01–N04 已接入；自动化及部分界面验证通过，真实采集验收待执行

## 1 评审结论与现状

两项需求均合理，纳入 macOS 首期 P0 补充范围。多模型便于在成本、效果和本地处理之间选择；双音源是完整记录线上会议的必要能力。这里的“模型”指文本分析服务，与本地 Whisper 转写模型分别管理。

| 能力 | 当前实现 | 本轮补充 |
| --- | --- | --- |
| 文本模型 | 已改为多配置与不可变版本、独立 Keychain 引用、会议绑定 | 假服务验证隔离/切换/取消/迁移；真实服务组合待用户验收 |
| 线上会议录音 | 三种模式、三秒不落盘电平检查、独立麦克风控制和单路故障降级已接入 | 假设备写盘/缺口验证通过；真实权限、路由与线上对话待验收 |
| 双轨同步 | 主时钟对齐与有界持续修正已接入 | 两小时 ±500ppm 模拟通过；真实硬件漂移和蓝牙路由仍待测 |

本轮已实现增补功能并构建应用；完成边界与证据见[增补功能开发验证](./增补功能开发验证.md)，不把假设备测试视为真实采集验收。

## 2 多模型配置的产品规则

### 2.1 配置管理与会议选择

设置中提供“文本分析模型”列表，支持新增、编辑、复制、连接测试、设为默认、停用和删除。每项显示名称、服务地址、模型 ID、本地/远程、可用性和最近测试时间；列表和会议顶部明确当前选择。

例如可保存“DeepSeek 日常”“本地离线”“另一账号的 DeepSeek”。同一服务地址允许配置不同模型、不同账号；显示名称只是标签，不能作为身份或授权依据。服务模型 ID 由用户填写，不依赖厂商提供模型列表接口。

- 全局默认仅用于新会议的初始选择；没有可用默认时允许仅录音转写。
- 每场会议固定 `profile_id + config_version`。总结、问答、待办和最终纪要共用本场选定配置；本轮不增加按功能自动路由或多模型并行投票。
- 新会议仍默认关闭分析。选择了远程模型不等于授权外发。
- 编辑配置创建不可变新版本，已有会议继续使用所绑定版本，界面提示“有新版本可选”；改变全局默认不改变历史或活动会议。
- 会前、会中、会后均可切换。本场切换不停止录音、转写或改变 Whisper 模型。
- 失败只提供重试或用户选择其他配置，不自动切换到默认、其他厂商或远程服务。
- 停用/删除按归档处理：禁止新任务使用，提示受影响会议重新选择；保留旧任务和产物的脱敏模型信息，不改写旧结果。不能静默替换历史绑定。

### 2.2 配置与凭据

| 字段 | 规则 |
| --- | --- |
| profile_id / config_version | 应用生成稳定 ID；每次配置变更产生递增版本 |
| display_name | 用户标签，可重名；界面用服务/模型辅助区分 |
| protocol / base_url / model | 首期 OpenAI-compatible Chat；保留 URL 路径前缀，只追加 `/chat/completions` |
| context_tokens / max_output_tokens / timeout_seconds | 正整数、有界；上下文预算包括输入和输出；不假定厂商默认相同 |
| credential_ref | 独立 Keychain 引用，不含明文凭据；不能仅用 Base URL 作为 Keychain account |
| capability_result | 固定测试文本得到的能力、测试版本与时间；配置变化后标记待重新测试 |

API Key 仅在后端进入 Keychain，前端查询返回 `has_api_key`。保存时明确 `keep / replace / clear`，不能把空输入误判为清除。复制配置默认不复制密钥；修改服务地址必须重新指定凭据，不把旧服务密钥发给新地址。同地址不同账号也不能隐式共享密钥。

凭据轮换/清除使对应旧凭据停止用于新请求及重试，取消使用它的在途任务并隔离迟到结果；只影响引用该凭据的会议。旧配置版本仍保留非密钥历史信息，显示凭据已失效，用户需显式采用新版本。Keychain 清理待读取者释放后执行；应用不得为历史回放保留已撤销密钥。配置、会议、导出、日志与输入快照均不保存密钥。

连接测试使用固定无会议内容的文本；测试只表示该配置当时可用。流式与结构化能力分别记录，不把接口连通等同于会议语义质量通过。

### 2.3 会中切换与授权

1. 展示目标配置、服务地址、模型、本地/远程和拟发送内容类别；用户确认切换。本地与远程的识别仍按字面回环地址规则。
2. 切至远程配置时重新确认本场发送范围及是否启用定时分析；授权绑定配置版本、规范化目标和范围。未授权时可完成选择，但保持仅录音转写。切至本地无需远程授权。
3. 事务内检查会议 `expected_version`，更新配置绑定及授权，递增本场 `generation`。取消旧队列/尽力取消在途请求；任务发送前和写回前都重新检查，防止旧配置派发新请求或写回迟到结果。
4. 切换本身不补发历史全文。下次用户触发或已授权的定时分析按显示范围发送；若包含旧纪要、笔记、问答、待办和会议信息，必须纳入范围说明与上下文预算。
5. 已有结果保留原模型、配置版本、输入覆盖和时间。重新生成创建新产物；人工编辑保留。仅换模型不代表旧事实失效，原文修订过期与“由其他模型生成”分别显示。

授权对当前会议有效，定时总结不重复弹窗。切换配置、采用新配置版本或扩大范围需重新校验/授权；全局默认变化与无关配置编辑不撤销所有会议。已经发出的数据无法撤回。

## 3 线上会议的声音从哪里来

| 要记录的内容 | 采集入口 | 用户选择 |
| --- | --- | --- |
| 远端参会人讲话、共享视频声音 | 会议软件/浏览器在本机播放的系统声音 | “电脑声音” |
| 自己讲话 | 内置麦克风、耳机麦克风或 USB 麦克风输入 | “麦克风”，建议与会议软件使用相同输入 |
| 双方完整对话 | 两路同时采集 | “线上会议：麦克风 + 电脑声音” |

这里采集本机已播放的音频，不解析网络数据包，不需要机器人加入会议。戴耳机时，仅录麦克风通常无法记录远端声音；仅录系统声音也不能假定包含自己的麦克风。

### 3.1 操作流程与边界

会前选择“线下会议”或“线上会议”。线下预选麦克风；线上明确预选双音源，首次使用说明系统采集范围。首次默认保持麦克风模式，不因检测到会议软件自动开启系统采集。

用户可选具体麦克风，核对两个独立电平，再开始录音。预览由用户主动开启，退出预览释放采集，不落盘、不转写；未开启的音源不预览。启动时所有选定音源成功才进入正常录制，部分失败先回滚，再由用户明确选择单音源重试。

- 系统级采集可能同时录到其他应用、通知和音乐，界面持续显示“所有应用声音（排除本应用）”；只录指定会议应用作为 P1，浏览器标签页隔离需另验，不先承诺。
- 本应用回听声音排除在系统轨外，不保存屏幕视频；权限名称随 macOS 版本变化，解释只处理音频的用途，拒绝时显示缺失音源及设置入口。
- 会议软件中的“静音”不能作为本助手麦克风关闭的依据。助手提供独立“暂停采集麦克风 / 恢复”控制和常驻状态；关闭时不读取/保存麦克风数据，系统轨可继续，时间轴记录为主动关闭。重新开启是用户明确动作；暂停后继续需确认恢复麦克风，或仅继续电脑声音。
- 推荐耳机，避免扬声器声音再次进入麦克风造成双录与回声；外放声学回声消除作为 P1 专项验证，不用会议软件已有降噪替代本应用验证。
- 两路音源不等于两位说话人，系统轨可能包含多名远端参会者；不自动把声音标成人名，重叠讲话识别质量单独评估。
- 不改变会议软件的设备、音量和静音设置。系统音量、输出路由、蓝牙通话模式会影响实际音频路径，需要实测；不能仅凭扬声器音量为零判断系统轨成功或失败。

### 3.2 macOS 实现

沿用 macOS 14+ 的独立入口：AVAudioEngine 采麦克风；ScreenCaptureKit 设置 `capturesAudio = true`、`excludesCurrentProcessAudio = true`，只注册音频输出。Apple 官方分别定义了[音频采集开关](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/capturesaudio)与[排除本应用音频](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/excludescurrentprocessaudio)；实际授权及会议兼容性仍以目标系统测试为准。

```text
麦克风 ─ AVAudioEngine ───── 重采样 ─ mic WAV ─────┐
                                               ├─ 同一时间轴混音 ─ 本地 Whisper
系统声音 ─ ScreenCaptureKit ─ 重采样 ─ system WAV ──┘
```

两轨分别保存 16kHz/16bit/mono WAV，混音按需计算；两小时双轨约 460.8 MB（十进制，不含数据库、模型及导出）。每帧带音源、样本计数、单调时钟锚点和 epoch；采集回调不进行模型调用或磁盘阻塞。

以音频 host time 对齐初始偏移，持续测量样本时钟漂移，通过有界持续重采样修正。真正缺帧记录缺口，只在混音计算时填充，不把它伪装成实际录到的静音。修正不能移动已提交证据的时间位置。当前约 4 秒分段落盘；新分析配置不触及采集线程或音频文件。

### 3.3 音源失效与降级

每路分别显示准备中、正常、主动关闭、失效；正常静音与设备错误分开。持续无声只提示检查，不能仅凭低电平判定断流。权限、设备/流错误、队列溢出等形成明确异常事件。

开始后的单路故障应保留另一条已选音源继续采集，界面进入“部分录制”，记录故障路缺口并提示恢复；设备重选或扩大音源需要用户操作。两路均失败则中断录制。磁盘失败停止整场采集；睡眠中断明确记录，不能补造音频。运行版已实现源级异常降级；全局睡眠、共享队列溢出、磁盘错误仍中断整场，不能承诺所有故障均可单源继续。

## 4 数据与接口改造

### 4.1 模型配置的存储

复用已有 `model_configs(id, version, config_json, credential_ref)` 保存不可变版本，新增稳定配置目录（名称、启用/归档、当前版本）、默认配置引用和会议到配置版本的复合外键。现有 `meeting_configs` 保存本场配置/权限快照；任务快照额外固定 `profile_id, config_version, consent_version, generation` 与输入修订、模板、范围，产物保留这些溯源信息。

模型目录以数据库为事实来源。用户运行设置只保留默认配置引用等偏好，不能继续从全局 `Config.analysis` 决定历史会议的模型；采集与 ASR 配置不随之迁移。开发配置可兼容旧 `analysis` 单项导入，未来扩展 profiles 时只作首次导入/显式导入，不能每次启动覆盖用户配置。

采用新的追加迁移，不修改已存在的 0001–0004。升级前一致备份，迁移与版本切换有事务/CAS，失败可重启重试。旧单项配置导入为一个默认配置，Keychain 从按 URL 索引迁至独立引用，写入校验成功后再清理旧项；Keychain 与 SQLite 不能跨系统原子提交，需可重入迁移记录和孤儿凭据清理。

已有任务若能从快照恢复真实模型则保留，否则标“旧版配置未知”，不伪造来源。已有会议一次性进入待选配置/待确认分析状态，录音与旧产物保留；不继承无法证明等价的旧远程授权。

### 4.2 逻辑命令与状态

| 命令 | 关键契约 |
| --- | --- |
| model_profiles | 脱敏目录、当前/默认版本、has_api_key；可查询历史版本 |
| save_model_profile | 配置校验；update 带 expected_version；密钥操作 keep/replace/clear；返回新版本 |
| test_model_profile | 绑定 profile_id + config_version，固定文本；返回能力与测试时间 |
| set_default_model_profile | 只改变新会议初始选择，不自动开启分析 |
| switch_meeting_model | meeting_id、expected_version、profile_id、config_version、授权；事务更新本场 generation |
| archive_model_profile | 提示受影响会议数；禁止派发、取消关联在途任务并保留历史 |
| set_microphone_enabled | meeting_id、expected_version、source、enabled；本轮支持麦克风关闭/恢复，改变采集范围需显式操作 |

这些操作已接入受限 `dispatch` 枚举；save_model_profile 用可选 profile_id/expected_version 区分新增与编辑，删除按归档处理。会议快照增加当前配置、是否新版本可用、授权状态、双路状态/设备及缺失范围，不向前端返回秘密或任意文件路径。

## 5 开发顺序与验收

1. N01：模型版本与迁移、独立 Keychain 引用、脱敏 DTO，先用假服务验证同地址多账号不串 Key。
2. N02：配置列表/编辑/测试/默认与会议选择，移除分析对全局单配置的依赖。
3. N03：会中切换、授权与写回栅栏；验证旧任务迟到、重启恢复、停用删除和凭据轮换。
4. N04：线上模式、逐路状态、独立麦克风控制、单路故障降级与漂移修正。
5. N05：打包应用实际授权与会议软件矩阵、耳机/蓝牙/外放、两小时双源稳定性；结果登记后再关闭验收项。

N01–N03 与 N04 无业务依赖，可按资源安排；集成顺序先保证录音完整，再验证模型切换不干扰录音。详细任务在[开发计划](./开发计划.md)，新增 R13–R22 / A21–A26 / TC-21–TC-26 在[需求](./本地会议助手_需求文档.md)和[测试验收](./测试验收文档.md)。新增用例的自动化部分和隔离界面流程已执行；真实设备部分仍待验证，不能把整项 TC-25/26 标为通过。
