# AP04b · 真实外放与双讲验证

2026年10月19日，用户要求优先真实外放音质和双讲，并确认使用电脑扬声器、可以现场配合。两小时稳定性明确暂缓，保持未验收；本轮不据此阻塞声学质量测试，也不宣称全设备验收完成。

## 方法

- 独立 CLI `--check-acoustic-aec`，必须显式指定不存在的 `HELMMEET_ACOUSTIC_ROOT`，时长限定5–90秒，默认65秒；目录已存在拒绝运行。先写空白配置并使用无凭据适配器，只启动正式采集和磁盘增强 Worker，不启动 ASR/LLM，不读个人开发配置或 Keychain。
- 复用 AVAudioEngine + ScreenCaptureKit、正式分片落盘/样本时轴、路由观察与 AEC 派生链路，NS关闭。主线程运行原生事件循环；停止采集后等待最多30秒增强完成，停止并 join Worker。
- Python协调器使用本机已安装的 Tingting 语音生成固定普通测试语句，由独立 afplay 进程外放，确保不是被SCK排除的应用自身音频。外放声是合成语音，扬声器/房间/麦克风采集为真实声学路径；双讲的近端必须是现场本人，不能用同一扬声器播放第二个人声冒充。
- 68秒采集，65秒外放脚本：0–4秒环境，4–25秒远端独讲，25–29秒提示，29–41秒近端独讲，41–45秒提示，45–61秒双讲，61–65秒结束提示。统计窗口避开提示和边缘；实际采集时轴通过已录系统参考与播放脚本相关对齐，记录相关系数。
- 原始麦克风、系统参考、AEC麦克风及试听切片仅在本机新建临时目录保存。原轨不修改，不接触正式会议库，不上传。脚本仅显式手工运行，不进入自动 verify 或 CI。

```sh
python3 tests/integration/check_acoustic_aec.py prepare --folder /private/tmp/helmmeet-acoustic-UNIQUE
# 确认真人就绪、扬声器外放，明确授权后才执行 capture：
python3 tests/integration/check_acoustic_aec.py capture --folder /private/tmp/helmmeet-acoustic-UNIQUE
python3 tests/integration/analyze_acoustic_aec.py --folder /private/tmp/helmmeet-acoustic-UNIQUE
```

分析脚本使用本机已有numpy，不是应用运行时依赖。准备仅生成文件；capture会真实采集、保存、播放。中断时先停止播放器、通知采集封口和join；原始文件保留便于定位。CLI失败仍需查看本机诊断结果，不自动当作成功。

## 判定边界

远端单讲只统计参考有信号且AEC覆盖为applied的20ms块；报告麦克风原声→AEC能量变化，包含环境噪声，不冒充完全隔离的回声功率。双讲不能用整体音量下降证明有效，也没有独立干净近端真值可计算近端增益。生成等增益的原声/AEC配对，以及“原声→1秒静音→AEC”的AB文件；由参与者确认声音自然度、可懂度、词尾及咔哒/抽吸声。

本机采集无缺段、无削波、参考相关良好，只证明采集和处理链路；还需现场参与和试听结论才能关闭真人音质验收。两小时、USB/蓝牙、切设备/睡眠和标注CER独立保留待验收。

### 实机发现及修复

发现部分4秒片段封口早于下一次250ms路由观察，Worker立即读取的路由水位落后于段尾，导致虚假的route_unobserved短缺口，滤波器清空并重新预热。修复为：录制中同时等待密封系统参考及路由观察到片段末尾，沿用有效录制时间最多8秒的有界等待；暂停/结束立即结算，不修改raw。只有同一路由后续观察确认后才延长覆盖，真正切换间的未知区间仍旁路，不倒填。

新增回归覆盖参考已密封但路由水位稍落后、下一稳定观察后连续处理、不产生边界重置、观察永久失效仍有界旁路；既有真实切路由未知区间测试保留。新增只复制诊断原轨和数据库到新目录的离线重放入口，清除副本的旧派生后重新处理，原始capture不覆盖。

修复后在replay目录从同一段真实原轨重放：原声/系统导出SHA256均与采集版本一致；route_unobserved从5处降至1处（保留采集起始尚未确认路由的真实区间）。全程AEC adopted从41.000秒升至47.610秒。
