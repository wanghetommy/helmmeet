# ADR-0002：会议类型与受限对话运行时

状态：已采纳并实施首版。更新：2026年10月19日。Pi1.3.0/Node22.22.2、真实SDK合成代理/工具/恢复/取消及叠加沙箱已验证；实机语音与Intel硬件验收另列。

会议类型与模板版本独立于文本模型配置。一个会议绑定一个主类型/模板快照，以类型检查清单和会前/中/后指令驱动同一对话引擎。对话持久化到应用数据库，与会议证据修订绑定；不建立跨会议隐式记忆。

先在现有 Rust 模型适配上交付基础持续对话，再验证 Pi SDK 的受限检索编排。候选实现放 agent/，通过 stdio sidecar 调用 Rust 的会议工具及模型代理。Rust 保留数据库、凭据、网络授权、快照和最终写回权；Pi 默认编码工具与宿主资源发现不进入产品。

原因：不同会议需要不同诊断标准，持续追问需要消息历史和证据核对；不需要按类型维护多个 agent。Pi 可减少工具循环和会话编排代码，但默认行为、依赖、运行时、历史恢复和模型代理都带来新增集成成本。

退出条件：锁定版本通过自定义 provider、工具调用、取消/预算、无隐式资源读取或网络、历史恢复、打包与宿主限制检查。若不满足，保留基础对话，并根据实验评估 pi-agent-core。未经验证不能仅凭 tools 白名单宣称实现 OS 沙箱。

代价：新增模板版本及聊天迁移、会话授权范围、Node 打包和两套运行时契约。每回合只运行一条生成路径，不增加静默模型回退或重复外发。

完整设计与官方资料见[会议类型与对话助手方案](../会议类型与对话助手方案.md)。


实施更新：全局入口按明确会议/活动会议/通用范围打开数据库会话，语音和文字共享同一Pi引擎与聊天历史；旧基础QA迁入v11会话并保留历史引用。Rust拥有凭据/HTTP/工具数据和发布权。sidecar携带独立Node生产依赖，用macOS sandbox-exec和Nodepermission限制读写/网络/子进程；负向测试真实执行，运行时不可用时不静默降级。动作目前限待用户接受的准备/笔记草稿；没有任意录音工具。最新实现与待验收见[小舵开发验证](../小舵全局助手开发验证.md)。
