# 可行性评审

评审日期：2026年10月18日 · 对象：需求 V0.2、技术方案 V0.2 · 修订后：V0.3

## 1 结论

**有条件可行，适合先实现 Apple Silicon Mac 个人版。**Tauri/React + Rust + macOS 原生采集 + whisper.cpp 路线成立，现有方案也正确区分了本地转写与可选远程文本分析。主要不确定性集中在长时间采集可靠性、实时管线的实际吞吐和模型分析质量，需要目标机数据证明。

本次已完善文档和初始化工程，尚未证明 P0 产品可用。用户提供的 large-v3-turbo 文件已登记本机配置；存在性与 hash 检查不能替代实际推理。

## 2 可行性与工程代价

| 能力 | 判断 | 必须验证的前提 |
| --- | --- | --- |
| 麦克风与系统音频 | 可实现，原生适配风险较高 | AVAudioEngine / ScreenCaptureKit 在打包应用中的授权、回调、设备中断、双源时钟 |
| large-v3-turbo 本地近实时转写 | 有条件可实现 | Metal、重复窗口成本、温升、统一内存争用、长会议积压；不能仅凭模型名承诺 15 秒 P95 |
| 单会议检索与回听 | 可实现，风险可控 | 时间轴统一、中文短词回退、引用绑定历史修订 |
| 摘要、问答、待办 | 可实现，质量依赖所选文本模型 | 上下文预算、分批覆盖、结构化输出与事实抽查；证据 ID 有效不代表语义正确 |
| 离线与崩溃恢复 | 可实现，需要专门设计 | 文件先持久化、数据库补账、幂等恢复、强退与断电分别测试 |
| 四端共用 | 可复用协议和业务规则 | 各端采集、后台限制、模型档位和打包各自验证，不作为 Mac P0 的发布依赖 |

官方资料核对：whisper.cpp 提供 Apple Silicon/Metal、C API 和流式示例，示例不能替代产品管线；模型卡标注 turbo 为 809M 参数。[whisper.cpp](https://github.com/ggml-org/whisper.cpp)、[模型卡](https://huggingface.co/openai/whisper-large-v3-turbo)。

系统采集使用 Apple 框架，明确排除应用自身音频；授权体验必须从真正的应用进程验证。[Apple 示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)、[排除本应用音频](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/excludescurrentprocessaudio)。

## 3 原方案需要补强的地方

| 风险 | 影响 | 本次修订 |
| --- | --- | --- |
| “一次 AI 开发”被当作质量保证 | 把代码生成当作真实设备验收 | 改为可连续推进的 M0–M5 里程碑，给每阶段退出证据 |
| WAV 关闭后才入库 | 强退留下孤儿音频或错误索引 | 创建前登记 writing；同步后 sealed；启动扫描补账与修复 |
| 双音源时钟只写概念 | 长会议逐渐错位、重复拾音 | 原始时钟锚点、持续重采样、漂移指标与双脉冲测试 |
| 覆盖与“有文本”混同 | 静音和缺失无法区分 | 采集/ASR/分析各自区间；静音是处理结果，缺失单列 |
| 证据有效等于事实正确 | 引用存在但内容不支持决定 | 结构校验之外增加人工语义依据抽查，明确待办 precision/recall |
| 只用 FTS trigram | 单字/两字中文查不到 | 三字及以上索引，短词参数化 LIKE 扫描本场转写，穷尽问答另走全量覆盖 |
| 仅停止网络请求 | 撤销授权后旧结果继续写回 | 授权版本/generation 和事务写回栅栏；删除同样处理 |
| 日期只用会议开始日 | 跨午夜发言“明天”错一天 | 用证据在 epoch 中映射出的当地日期 |
| 骨架与目标产品混淆 | 演示 UI 被认为已经录音 | 明确 unavailable，禁用录制，不生成模拟转写 |

FTS5 trigram 对短于三个字符的全文查询有限制，因此短词回退是产品正确性要求。[SQLite FTS5](https://sqlite.org/fts5.html#the_trigram_tokenizer)。

## 4 优先决策

- 保留 macOS 14+、arm64、推荐 16GB 的规划基线；最低配置未验证。大模型和 ASR 同机时必须额外压测。
- 默认依用户提供的完整 turbo 模型验证 Metal；量化是显式可选项，不能静默换模型或云端。
- P0 不做说话人分离、外部任务写入、自动发送、云同步或向量数据库；这些不会解决采集可靠性。
- 默认仅录音转写；远程分析按会议与目标服务授权。所谓 OpenAI-compatible 必须逐服务探测，不能承诺所有协议特性兼容。[Ollama 兼容说明](https://docs.ollama.com/api/openai-compatibility)。
- Tauri WebView 不得请求任意模型地址；新增应用命令还要用 AppManifest 和 capability 限制窗口范围。[Tauri capabilities](https://v2.tauri.app/security/capabilities/)。

## 5 资源与交付判断

两小时双轨语音 WAV 约 460.8 MB，另计转写、模型、导出临时副本。磁盘预警应预留清理与关文件空间；不能因剩余空间高于阈值就忽略写入失败。

不在缺少基准和实施者产能时承诺固定日期。开发计划提供顺序、依赖、测试和退出门槛；M1/M2 完成后才能根据真实吞吐与集成问题估算交付时间。签名和公证、模型许可和第三方清单属于分发前门槛。

可立即推进工程与自动化；真实采集需要授权和现场条件，远程质量测试需要用户选择的服务。所有未完成项保留为计划或待验证，不构造通过记录。
