# 接口与数据协议

协议版本：1 · 日期：2026年10月18日

## 1 当前实现与后续协议

当前注册 `get_system_status` 和受限枚举分发命令 `dispatch`。前端调用 `dispatch({operation:{kind,...}})`；kind 为 Rust Request 枚举定义的操作，不接受任意 shell、路径或 URL 执行。能力位表示对应代码已接入，不表示模型已加载或权限已授权。当前操作与 DTO 见 apps/desktop/src-tauri/src/commands.rs 和 apps/desktop/src/bridge.ts。下面表格为逻辑操作契约，尚未实现的高级能力见运行记录。

新增命令须同时修改 Rust handler、AppManifest 命令清单、Tauri capability、TS 类型和错误用例。前端只拿 DTO，不能返回 Keychain 内容、API Key或任意文件句柄；模型/数据路径仅受控展示，不授予按路径读写能力。

## 2 时间、版本与范围

- JSON 一律 snake_case，ID 为应用生成的不透明字符串；不能使用模型生成的 ID 写主记录。
- 录音位置为安全整数毫秒，半开区间 `[start_ms,end_ms)`，要求 `0 <= start_ms < end_ms`。有效时长不包括主动暂停。
- 音频保留原始样本计数与单调时钟锚点。墙钟使用 RFC3339 UTC 字符串，会议时区使用 IANA 名称，不能用 UTC 墙钟计算音频间隔。
- transcript 快照保存具体 `segment_id + revision` 列表及 hash，不只保存最后段号。覆盖列表与快照关联；缺失/失败分别列出。
- 会议 `generation` 在撤销授权、删除或使在途结果失效时递增。配置版本、人工 revision 与授权版本均进入任务输入快照。
- 业务提交先事务落库，再发事件。事件 sequence 按会议递增，运行时重启以新快照恢复；不能靠事件流作为唯一事实来源。

当前服务使用会议 `version` 和转写/待办修订号进行并发保护，涉及普通状态的完整 CAS 扩展仍按验收推进；使用会议 `version` 进行普通状态 CAS，`generation` 专用于在途结果隔离；不能把领域枚举或单会议唯一索引当作完整并发控制。SQL 初始迁移仅是基础，服务接入时按迁移追加字段。

scope 仅允许 `all_confirmed`、`recent`（明确 duration_ms）、`selection`（明确片段和修订列表）。后端重新验证范围、会议归属、当前权限及上下文预算，不能信任前端传来的覆盖字段。

## 4 事件与错误

事件：`protocol_version, meeting_id, event_id, sequence, emitted_at, type, payload`。业务事件包括 recording_state_changed、transcript_committed、artifact_ready、actions_changed、job_failed；audio_level 与 transcript_partial 为可丢弃预览，不能持久化为事实。

统一命令错误 `{code,message,retryable}`。基本错误码已在 contracts 定义：NOT_IMPLEMENTED、INVALID_STATE、PERMISSION_DENIED、DISK_FULL、MODEL_UNAVAILABLE、VERSION_CONFLICT、CONSENT_REQUIRED、INVALID_EVIDENCE、INTERNAL。message 可读且不包含密钥、正文或原始请求头；更细错误按协议版本演进。

发现事件断号、重连或进程恢复时请求最新快照，不能默认重放旧请求。网络 retry 只重试可重试错误，自动上限为 2；JSON 修复最多 1 次，与传输重试分别计数。

## 5 数据库约束和仍需服务保证的事项

初始迁移包含会议、epochs、音频分段、覆盖、转写版本、配置、分析任务、产物证据、待办修订和清理队列。参会人身份、模板版本管理、聊天会话、笔记与全文索引将在对应阶段增加迁移。

数据库约束已覆盖：单活动会议、正向区间、状态枚举、任务键去重、跨会议与不存在修订引用拒绝。服务还须保证：current_revision 真实存在、修订不可变、禁止删除中的新写入、人工锁定字段、授权/版本原子写回、文件路径约束和日期解析。JSON 列的 json_valid 只检查语法，不等于业务 Schema 校验。

应用打开每个连接后启用 foreign_keys；运行库启用 WAL 与 synchronous=FULL 并验证文件 sync。迁移前做包含 WAL 的一致备份，失败回滚后继续使用原库。Python 内存库测试不能证明磁盘断电可靠性。

## 6 当前传输实现

运行版使用约 1.2 秒轮询完整会议快照恢复 UI；没有依赖瞬态事件保存业务事实。业务先落库，partial/电平为可丢弃的内存状态。上述统一事件信封是后续推送协议，当前不宣称已实现序列重放。分析适配器当前使用非流式 Chat Completions，后台显示任务状态；不支持的流式能力明确返回 false。错误当前为脱敏可读字符串，结构化错误码留作协议演进。

| kind | 请求与约束 |
| --- | --- |

授权 scope 新增 chat_context，显式说明问题、相关历史回答和用户补充背景；旧授权不能隐式扩大。聊天 DTO 包含 message_id、turn_id、role、status、sequence、来源/证据和覆盖标记；正式回答包含事实、待澄清项、明确阻塞、推测风险/建议。context 来源与 transcript 引用分开，不把用户背景或模型旧回答伪装成转写证据。

Rust→agent 使用带 protocol_version、request_id、turn_id 的受限 stdio 消息，按行分帧且限制单帧大小、并发待处理数和总输出。start_turn/cancel/dispose 为宿主操作；agent→Rust 仅允许限定工具读取及 model_request；反馈为 text_delta、tool_status、turn_completed/failed 等，均需校验回合身份及顺序。stdio 不是授权边界，Rust 只接受当前子进程和当前能力句柄，不信任 agent 声明的会议/模型/URL。stdout 仅写协议，日志脱敏，不含提示词、正文和密钥。

能力句柄由 Rust 绑定会议、会话、冻结修订、范围、模板/背景/模型/授权版本和 generation，每次工具读取与模型派发重验。model_request 仅接收受约束消息/工具/生成参数，不接受 API Key、任意目标或头；Rust 代理负责 tool_calls/tool_call_id、流式/非流式转换、取消和总预算。现有摘要 HTTP 路径不能直接代替该桥接。

终态预览与提交分开；最终产物必须通过本地结构、证据与同事务版本栅栏。流式断号/重连后读应用 DB 快照，不重发用户消息或重放模型请求。具体运行时、调度和迁移见[扩展方案](./会议类型与对话助手方案.md)；协议细节与 SDK 适配须在 T00/T02 固化后实现。

## 9 工作区与自动总结（拟议接口，尚未注册）

继续走受限 dispatch。仅修改文档不表示这些 Request 或剪贴板权限已存在；实现时同步 Rust/TS/Schema、Tauri 权限、错误和迁移。前端不获得通用文件/剪贴板读取能力。

| kind | 请求与约束 |
| --- | --- |
| read_transcript_snapshot | meeting_id、source=current/asr_original、scope=all_confirmed/selection、with_timestamps；返回后端格式化文本、snapshot_id、片段/修订清单、截至时间及 hash，按本场验证，无 partial |
| copy_transcript | 本场/来源/明确范围/时间戳选项、client_request_id，可引用已验证 snapshot_id；冻结并写入用户所选文本，结果包含原操作 meeting_id/source/snapshot_id/字符数/状态；只有实际写入成功才 copied=true |
| set_summary_schedule | meeting_id、expected_version、enabled、mode=realtime/interval_60s/interval_180s；需要现有模型及自动总结范围授权，更新独立 schedule_version/自动代次，不更改模型或聊天授权 |
| summarize_now | 沿用逻辑入口，增加 source=manual；与同范围在途/待派发总结合并，不新建重复任务 |

SummarySchedule DTO 包含模式/开关、策略参数版本、state（off/collecting/pending/running/paused/failed_paused/waiting_tail）、成功覆盖快照、未覆盖修订数和暂停原因。legacy_minutes 只供旧 5/10 分钟读取/迁移，不允许新 UI 默选成更高频档。实时初始策略为约 60 个非空白字符或 15000ms；时间为扣除暂停的单调运行时长，不持久化 Instant，也不依赖 WebView 定时器。

调度维护已成功处理的修订集合与独立新窗口：完整业务任务到终态后才重开；有积压时从完成时计时，无积压等下一条确认文字。积压不计入返回后新字符阈值，但进入下轮输入并可由时间截止触发。排队只保存一个自动意图，实际派发时冻结最新快照。source=automatic/final_flush 的结果同时校验自动代次、任务身份及既有授权/配置/generation，不能因关闭自动总结而拒绝无关的手工结果。

会议纪要产物结构增加 current_topic、logic_outline、progress、disagreements/open_questions 和 evidence。logic_outline 是可折叠讨论提纲，推断关联标为助手归纳；不能导出隐藏推理。用户侧只有 `minutes` 一套展示产物，实时检查点与会后草稿/确认版本使用统一的状态胶囊（实时更新、待确认、已确认、需要重新确认、覆盖不完整）；`stage` 仅作为兼容的内部任务/存储类型。待办仍归共享 action_items。`summary_context` 明确包含必要旧检查点及其原文，不能用聊天授权替代，也不能隐式包含聊天历史。

本节细化[工作区优化方案](./会议工作区与自动总结优化方案.md)，具体 API 字段在 W01/W02 实现前固化；当前第 7 节 interval_minutes 仍是运行版协议，不把新字段套入旧接口假装可用。

## 2026年10月19日音频实现补充

`playback` 仍返回 16kHz 单声道 PCM16 数组及 start_ms/end_ms，未增加外层命令。前端复用单 AudioContext 按精确样本时长排队、提前获取下段，不再每 30 秒重建媒体元素；取消代次拦住旧会议迟到响应。欠载返回可见暂停状态，音量仅影响回听。混音采用会议音源集合的固定增益，不因一路包缺失而抬高另一路；独立轨道导出保持原增益，原始 WAV 不被覆盖。

回答结构为blocks:[kind,text,sources]、evidence:实际工具返回且被引用的来源、coverage:{scope,through_ms,transcript_returned,transcript_total}。kind为meeting_fact/knowledge/suggestion/unanswered；历史迁入块为legacy。source_id含会议segment/revision或资料集合/version/chunk；引用提供原文，原文更新后stale=true；assistant_playback_overlap=true的片段不得自动确认会议事实。coverage计数仅代表本轮返回给Agent的原文，不承诺语义全覆盖。

总结/纪要内部模型协议补记：任务类型task_type，allowed_evidence为本批segment_id短编号/revision清单；transcript/parts中的编号仅本次有效，HTTP返回经Rust映射回真实ID和修订再校验入库。dispatch/Artifact.evidence继续返回真实segment_id/revision，不向UI泄露临时编号。coverage新增assistant_playback_overlap_segments；非零时产物保持incomplete，并在UI/Markdown解释待核对范围。input_snapshot保存excluded_manifest和citation_policy，原稿不随排除删除。


总结/纪要引用格式兼容增补：模型返回的evidence推荐为["ref_001"]；Rust按本请求冻结映射展开为真实segment_id/revision。旧的{segment_id,revision}数组仍可接受，但未知编号、跨批引用和错修订均拒绝，Artifact/DTO/SQLite仍只保存真实引用。无依据的unanswered条目规范为“会议中未明确”；其原措辞不持久化为事实，事实/决定/风险/问题及行动的空引用仍报错。空引用与单条超过32个引用分别报告条目位置及修复要求。


R60–63增补：仍通过既有dispatch命令，新Request::PrepareAsr（kind=prepare_asr，无会议正文参数）将请求交给原ASR worker，返回{ready:true,cached:boolean}；没有文件路径/音频/凭据DTO。加载有界180秒，失败不启动设备；前端用本次启动标记拦截取消后的迟到结果。底层录音持久化规则不变。

propose_action.action新增todo，仍为pending草稿；assistant_accept接受后写本场action_items与human action_revision，空负责人/期限、确认且todo、字段保护，使用proposal_id作幂等ID并检查会议generation。没有会议不得保存。get_context的user_records仅在本场context_consent为true时包含有限笔记和待办，作为用户背景，不能用于伪造meeting来源。五个工具和Tauri顶层命令/capabilities不增加。
