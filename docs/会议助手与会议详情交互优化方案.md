# 会议助手与会议详情交互优化方案

版本：v1.0

日期：2026年10月21日

状态：P0–P3 首版及 R83 全局悬浮交互已实现，真实窗口和完整无障碍验收待继续。

## 1. 现状与问题

当前有两条进入助手的路径：

1. 左侧导航进入全局助手，默认是通用会话，也可以切换历史会议；
2. 会议详情页的分析区域中还有“会议助手”标签，使用本场会议上下文。

两个入口都叫助手，但作用范围不同。用户容易产生三个疑问：当前问的是通用问题还是本场问题、两个聊天是否共享历史、从会议页面离开后正在回答的任务是否还在继续。

会议详情页目前还把标题/操作栏、记录区、右侧“会后整理”面板和多层标签拆开。会后阅读时，会议标题和总结内容缺少整体关系；右侧面板占据固定宽度，正文可读区域偏小；低频操作和主要内容混在同一层级。

## 2. 总体方向

### 2.1 一个助手入口，多个上下文

产品只保留一个助手能力，入口名称固定为“助手”或“小舵”，不再使用“全局会议助手”和“本场会议助手”两个产品入口。

助手仍然有上下文范围，但范围通过界面中的上下文标记表达：

- `通用会话`：准备会议、讨论方法、跨会议的用户问题；
- `当前会议 · 会议名称`：本场转写、会议纪要、行动事项和本场聊天历史；
- `历史会议 · 会议名称`：只读回顾指定会议。

上下文切换必须显式可见。用户隐藏聊天、切换页面或收起浮层时，不创建新会话、不清除草稿、不取消正在执行的问答。

### 2.2 助手默认悬浮，正文默认最大化

会议详情页默认只展示会议内容。助手以右下角悬浮入口存在，打开后使用抽屉或浮层承载聊天；不打开时不压缩转写、总结或纪要区域。

助手浮层只负责对话和状态，不承载会议主导航。用户需要阅读会议内容时可以关闭浮层，回答仍在后台继续，完成后在入口显示结果提示。

### 2.3 会议详情页采用“标题—操作栏—内容区”

会议详情页只保留一个主工作区：

1. 标题区：会议标题、类型、录制状态、时长和处理状态；
2. 操作栏：当前阶段最重要的操作，低频操作进入更多菜单；
3. 内容区：原文、会议纪要、行动事项和录音回听在同一内容画布中切换。

“会后整理”作为内容区的产品标题或阶段标签存在，不再作为旁边独立的第二块页面。

## 3. 助手入口和悬浮交互

### 3.1 左侧导航

左侧导航保留一个入口：

```text
会议列表
助手
资料与词库
全局设置
```

点击“助手”时：

- 如果当前已选中一场会议，默认打开该会议上下文；
- 如果当前没有会议，打开通用会话；
- 如果当前正在录制另一场会议，显示“当前助手范围”标记，并提供“切换到正在进行的会议”按钮；
- 不因为进入全局助手而自动改变模型、会议授权或录音状态。

助手页面顶部显示上下文胶囊，例如：

```text
小舵助手    [当前会议 · 需求专家知识库讨论 ▾]
```

上下文切换只改变后续问题的范围，历史聊天保留并按会话 epoch 隔离。

### 3.2 悬浮入口

除独立助手页面外，所有页面右下角提供同一个固定的助手入口。会议进行中时它绑定当前会议；没有进行中的会议时只提供文字聊天，不能伪装成监听状态：

```text
        ┌──────────────┐
        │  小舵  ●      │
        └──────────────┘
```

入口状态使用图标、颜色和文字标签共同表达，不能只依赖颜色：

| 状态 | 入口表现 | 说明 |
| --- | --- | --- |
| off | 灰色助手图标 | 语音助手关闭，文字助手仍可打开 |
| standby | 蓝色静态圆点 | 等待唤醒，不代表正在处理问题 |
| listening | 蓝色脉冲和麦克风图标 | 正在监听当前会议麦克风 |
| transcribing | 转写图标 | 正在识别语音问题 |
| thinking | 小幅旋转图标 | 正在检索或请求模型 |
| speaking | 扬声器图标 | 正在播报，可点击打断 |
| error | 红色提示点 | 最近一次任务失败，点击查看原因 |
| unread | 状态图标旁数字点 | 有已完成回答或需要查看的结果 |

悬浮入口的悬停或键盘焦点显示完整文字，例如“正在监听”“正在回答”“语音已关闭”。语音关闭时不能显示成“待唤醒”，避免用户误以为麦克风正在监听。

### 3.3 打开方式

- 点击悬浮框右侧名称区域：打开或隐藏右侧助手抽屉；
- 点击悬浮框左侧麦克风：进入语音输入；监听中再次点击提交，播报中点击打断并提问；
- 聊天输入区提供“语音输入”按钮，与悬浮麦克风使用同一会话；没有正在进行的会议时隐藏该按钮；
- `Esc`：关闭抽屉，不取消任务；
- 抽屉内点击上下文胶囊：切换通用、当前会议或历史会议；
- 任务完成后关闭抽屉：入口保留未读点，点击后回到对应回答；
- 拖动抽屉标题栏可以改变位置，位置限制在当前窗口内；关闭后再次打开保留本次应用运行期间的位置；
- 小屏窗口：抽屉变为底部或全屏面板，不覆盖系统关键操作；
- 录音进行中：浮层可以打开，但录音控制仍在会议标题区，避免误触结束会议。

### 3.4 语音状态整合

现有全局 `AssistantVoiceBar` 不再作为另一条入口长期占据页面顶部，已并入全局悬浮入口和助手抽屉：

- 入口显示实时语音状态；
- 抽屉显示“关闭语音/开启语音”“停止播报”“取消当前回答”等上下文操作；
- 语音开启仍需用户显式操作；
- 只在录制且麦克风有效时显示监听状态；
- 播报期间仍显示文字回答和引用；
- 自播音频不触发新的唤醒回合。

## 4. 会议详情页布局

### 4.1 桌面宽屏

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ← 会议列表   需求专家知识库讨论                    暂停 结束  ⋯     │
│             会议类型 · 录制状态 · 时长 · 处理状态                   │
├─────────────────────────────────────────────────────────────────────┤
│ 原文与录音   会议纪要   行动事项               资料  导出  更多    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│                         内容画布                                   │
│          当前标签对应的完整内容，尽量使用可用宽度                    │
│                                                                     │
│                                                   [小舵状态入口]      │
└─────────────────────────────────────────────────────────────────────┘
```

录制中的默认标签为“原文与录音”或“会议纪要”，取决于用户上次选择；会后默认进入“会议纪要”，没有可确认版本时显示实时更新内容和“生成纪要草稿”操作。

### 4.2 标题区

标题区只放与当前会议直接相关的信息：

- 返回会议列表；
- 会议标题；
- 会议类型；
- 录制/暂停/整理完成状态；
- 时长或处理进度。

标题编辑通过标题旁的编辑按钮或“会议信息”进入，不把长表单常驻在内容区。

### 4.3 操作栏

操作栏按会议阶段分组。

录制中：

- 暂停/继续录制；
- 结束会议；
- 音源与麦克风状态；
- 打开助手；
- 更多：会议信息、资料与词库、导出。

会后：

- 生成或重新生成纪要草稿；
- 发起续会；
- 回听录音；
- 导出；
- 更多：会议信息、资料与词库、删除。

同一操作只出现一次。资料、统一术语、回听和导出不再同时出现在标题区、子栏和内容标签中。

### 4.4 内容区导航

内容区导航统一为四个内容标签：

1. 原文与录音；
2. 会议纪要；
3. 行动事项。

“会议助手”从内容标签中移除，改由悬浮入口打开。这样内容标签只代表会议资料，助手只代表对话能力。

### 4.5 会后整理

会后页面采用一个连续内容画布：

```text
会后整理
├─ 会议纪要：同一套内容，按实时更新/待确认/已确认/需重新确认显示状态
├─ 行动事项：待确认、已确认、进行中和已完成
└─ 原文与录音：回查依据和播放定位
```

会议纪要是唯一面向用户的整理产物。实时更新是会中状态，待确认是会后草稿，已确认是正式版本，原文更新或覆盖缺口则进入需重新确认/覆盖不完整状态。内部可以继续保留实时检查点和 `stage/minutes` 兼容类型，但不能在界面上显示为“会议总结”和“会议纪要”两份并列文档。

## 5. 内容宽度和响应式规则

- 默认内容区使用可用宽度，正文最大宽度建议 1040–1180px；
- 原文阅读优先使用整宽，只有用户主动打开助手时才出现抽屉；
- 助手抽屉宽度建议 360–440px，不能改变会议内容的滚动位置；
- 宽屏下允许助手抽屉覆盖内容右侧，不强制把会议内容压缩成固定 55/45；
- 窄屏下助手抽屉变成底部或全屏面板；
- 保留键盘焦点、标签页切换、内容滚动位置和助手草稿；
- 悬浮入口不能遮挡当前段落操作、播放控制和结束会议确认框。

## 6. 实现分层

建议新增共享组件：

- `AssistantShell`：通用/会议上下文、会话、抽屉和草稿；
- `AssistantLauncher`：悬浮入口和状态展示；
- `AssistantStatus`：off、standby、listening、thinking、speaking、error；
- `MeetingHeader`：标题、状态和阶段操作；
- `MeetingContentNav`：原文、总结、纪要、行动事项；
- `MeetingContentCanvas`：单一内容画布。

现有 `AssistantChat` 继续作为对话内容组件，改为接收 `meetingId` 和 `open` 上下文，不再分别嵌入全局页和会议分析标签中复制入口逻辑。

后端不需要新增会议事实或聊天数据库表。现有 `assistant_open`、conversation epoch、历史索引、语音状态和回答覆盖可以复用。需要新增的主要是前端状态：

- `assistantOpen`；
- `assistantContext`；
- `assistantUnread`；
- `assistantDraftByContext`；
- `assistantPanelMode`。

如果要记住用户最后一次视图，可先使用本地 UI 偏好，不新增数据库迁移。

## 7. 实施顺序

### P0：统一入口

- 左侧导航固定为“助手”；
- 全局助手和会议助手使用同一个 `AssistantShell`；
- 在会议页面删除“会议助手”内容标签；
- 当前会议打开时默认带入本场上下文；
- 保留已有会话和历史，不改变后端会话 ID。

### P1：悬浮入口与状态

- 接入助手悬浮按钮；
- 统一语音状态和问答状态；
- 增加键盘、无障碍标签和错误/未读状态；
- 验证隐藏浮层不取消任务、不清除草稿。

### P2：会议详情重排

- 抽出统一标题区和阶段操作栏；
- 将“会后整理”改为内容区阶段标题；
- 原文、总结、纪要、行动事项合并成一个内容导航；
- 会后默认内容画布去掉右侧固定分割。

### P3：响应式和实机检查

- 宽屏、窄窗和键盘操作检查；
- 录制中、暂停、整理中、会后四种状态检查；
- 悬浮助手与回听、结束会议、错误提示、弹窗不互相遮挡；
- 助手状态、语音监听和任务完成提示不冒称录音或模型已成功。

## 8. 验收标准

- 用户在产品中只看到一个“助手”入口；
- 从全局入口和会议入口打开的是同一套助手交互，不产生两个相似聊天框；
- 用户始终能看到当前助手上下文是通用会话还是哪一场会议；
- 隐藏助手后仍能通过图标判断关闭、监听、转写、回答、播报和失败状态；
- 语音关闭时不会显示为正在监听；
- 会议详情页标题、阶段操作、内容区形成一个连续页面；
- 会议纪要、行动事项和原文可以在同一内容区域切换；
- 正文阅读区域比当前固定左右分栏更大；
- 低频操作不会与暂停、结束、生成纪要等主要操作竞争；
- 现有会议、聊天历史、模型绑定、录音状态和引用关系不改变；
- 不新增真实录音、远程模型调用或自动发送行为。

## 9. 不在本轮范围内

- 不把内部实时检查点暴露为第二套会议总结产品；
- 不把助手回答自动写入会议事实或正式纪要；
- 不开放常驻监听、自动语音打断或跨会议自动记忆；
- 不改变录音、ASR、模型授权和历史聊天的数据策略；
- 不因为 UI 合并而删除旧聊天、会议原文或历史产物。
